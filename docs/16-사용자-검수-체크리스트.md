# 사용자 검수 체크리스트

> 기준일: 2026-07-29  
> 목적: 코드·Maker 로그 검증과 사용자의 실제 조작/시각 검수를 구분한다. 이 문서는 기능 기획서가 아니라, 현재 구현이 기획대로 플레이되는지 확인하는 실행 기록이다.

## 1. 기록 방법

- 각 항목은 `통과` / `실패` / `보류` 중 하나로 표시하고, 실패면 재현 순서와 화면/로그를 남긴다.
- `자동 검증됨`은 Maker Build·Play 로그 또는 서버 거래 테스트로 확인한 사실이다. 사용자가 UI를 직접 눌러 본 결과를 대신하지 않는다.
- 아래 미구현 범위(F5, 맵 강화, F7-C, F7-D)는 실패가 아니라 **검수 대상 제외**다.

| 상태 | 뜻 |
|---|---|
| 자동 검증됨 | 현 코드와 Maker 로그에서 확인됨 |
| 사용자 검수 필요 | 실제 조작·표시·체감 확인이 필요함 |
| 대상 제외 | 아직 구현하지 않은 기획 범위 |

## 2. 시작·기본 루프

| 상태 | 사용자 확인 절차 | 기대 결과 | 기획 근거 |
|---|---|---|
| 자동 검증됨 | 새/초기화된 개발 프로필로 시작 | Gold 0, Worker01 1명, 수레 20칸, `farm01` 시작 | D7, F7-A/B |
| 사용자 검수 필요 | 블록을 조립해 Worker01 실행 → 광맥 채굴 → 수레 적재 → Depot 하역 | 손→수레→창고 순서가 보이고, 일반 광물은 계정 보유량에 반영 | D2, D3, F6 |
| 사용자 검수 필요 | 초보/깊은/보석 광산을 차례로 이동 | 현재 광산만 작업하고, 이동 뒤 일꾼은 Idle이며 계정 자산은 유지 | D6, F6, F7-B |
| 사용자 검수 필요 | Worker02를 구매한 뒤 프로그램/수레를 확인하고 재입장 | 구매한 일꾼만 추가되고, 일꾼별 수레·손 상태가 복구 | D4, F7-A/B |

## 3. 판매·진행

| 상태 | 사용자 확인 절차 | 기대 결과 | 기획 근거 |
|---|---|---|---|
| 사용자 검수 필요 | 돌/철/금광석을 각각 1개 및 임의 수량 판매 | 보유량이 줄고 Gold/토큰이 서버 거래 결과대로 반영 | D3, F7-B |
| 사용자 검수 필요 | 일반 광물 자동 판매를 켜고 보호 수량을 설정한 뒤 하역 | 보호분은 남고 초과분만 판매 | D3, F7-B |
| 사용자 검수 필요 | 깊은/보석 광산의 조건을 충족/미충족한 상태에서 입장 | 미충족은 거절, 첫 해금만 비용 차감, 재입장은 무료 | D6, F7-B |
| 사용자 검수 필요 | 수레를 1회 강화한 뒤 광산 이동 또는 Play 재시작 | 비용·용량이 한 번만 적용되고 강화 용량이 유지 | D4, F7-A/B |

## 7. 자동 점검 결과와 남은 주의점

- Maker workspace refresh와 Build Console에 새 오류는 없었다. Play에서 `MineSelectController`, `AccountProfileService`, Worker01, 광맥·marker 초기화가 확인됐다.
- `git diff --check`는 통과했다.
- `MineSelectUI.ui` lint는 오류 0건이며, 희귀 판매 팝업 내부의 정적 겹침은 제거했다. PC 우선 UI에 대한 모바일 터치 크기 경고와 기존 일반 판매/광산 선택 영역의 정적 겹침 경고 28건은 남아 있다. 실제 화면의 배치·클릭 가능 여부는 위 5절에서 반드시 직접 확인한다.

## 8. 판정

현재 결론은 **서버 규칙과 Maker 초기화는 기획과 일치하는 범위에서 통과**, **사용자 조작·시각 검수는 미완료**다. 5절과 희귀 광물의 직접 조작 항목을 모두 통과해야 “현재 구현이 오류 없이 기획대로 작동한다”고 판정한다.
