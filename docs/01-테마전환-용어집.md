# D0. 테마 전환·성장 시스템 용어집

> 최신화: 2026-07-26
> 이 문서는 D1~D8과 코드/데이터의 공식 명칭 기준이다. D7과 충돌하는 이전 표현은 이 문서의 정의를 따른다.

## 1. 핵심 월드 용어

| 한글 용어 | 코드 영문 표기 | 정의 |
|---|---|---|
| 광산 | `Mine` | 플레이하는 하나의 RectTile 광산 맵. 초보/깊은/보석 광산이 있다. |
| 광산 ID | `MineId` | 광산 진행·해금·강화에 쓰는 안정적 논리 ID. |
| 셀 | `Cell` | RectTile 그리드 한 칸. 좌표는 `(x, y)`다. |
| 광맥 | `Vein` | 일반 광물이 매장된 셀. `ReserveStage`가 시간에 따라 회복된다. |
| 특별 광맥 | `SpecialVein` | 일정 주기로 세션에 생성되는 강조 광맥. 일반 광맥보다 희귀 광물 확률이 높다. |
| 일반 광물 | `Ore` | `stone`, `iron`, `gold`로 구분되는 판매·해금·강화 자원. |
| 희귀 광물 | `RareOre` | `rare_stone`, `rare_iron`, `rare_gold`. 창고 하역 시 외형 도감과 별도인 희귀 광물 컬렉션에 등록되며 계정 패시브가 누적된다. 종류별 10단계 전에는 판매할 수 없고, 이후 판매 보상은 골드만 지급한다. |
| 매장량 단계 | `ReserveStage` | 광맥 현재 상태. `0=고갈 ~ 3=만재`; 채굴 시 -1, 회복 주기마다 +1이다. |
| 일꾼 | `Worker` | 프로그램을 배정받아 작업하는 자동화 캐릭터. 시작은 1명이고 최대 5명이다. |
| 수레 | `Cart` | 일꾼이 광물을 담는 개인 적재함. 기본 20칸, 강화 최대 50칸이며 도감 보너스는 별도 합산한다. |
| 맵 창고 | `Depot` | 현재 광산의 고정 하역 셀과 월드 마커. 하역 후 계정 창고 원장으로 반영된다. |
| 계정 창고 | `AccountStorage` | 돌/철/금/희귀 광물의 영구 계정 원장. 맵 전환과 재접속 뒤에도 유지된다. |
| 틱 | `Tick` | 시뮬레이션 최소 단위. 현재 0.4초이며 일꾼마다 틱당 최대 1액션이다. |

## 2. 자동화·프로그램 용어

| 한글 용어 | 코드 영문 표기 | 정의 |
|---|---|---|
| 블록 | `Block` | 프로그램의 명령 단위. 이동/채굴/싣기/내리기/반복/조건을 포함한다. |
| 프로그램 | `Program` | 블록의 순서·중첩 구조. 실행 시 일꾼에 복사된다. |
| 프로그램 라이브러리 | `ProgramLibrary` | 계정 공용 블록 설계도 보관함. 초기 3개, 최대 20개 슬롯이다. |
| 마지막 유효 프로그램 | `LastValidProgram` | 재접속 시 자동 실행 후보가 되는 마지막 서버 검증 통과 프로그램. |
| 자동 판매 | `AutoSell` | 보호 수량을 남기고 계정 창고의 일반 광물 초과분을 판매하는 설정. |

## 3. 성장·경제·외형 용어

| 한글 용어 | 코드 영문 표기 | 정의 |
|---|---|---|
| 골드 | `Gold` | 일반 광물 판매로 얻는 기본 비용 화폐. 일꾼, 수레, 맵 해금/강화, 라이브러리 슬롯에 쓴다. |
| 크리스탈 | `Crystal` | 외형 가챠 화폐. MVP에서는 튜토리얼/테스트 상점 등 무료 지급만 제공한다. |
| 광산 토큰 | `MineToken` | 이전 광산 대표 광물 판매로 얻는 해금 조건 화폐다. 이후 일일/주간 과제를 추가하면 보조 획득처가 될 수 있으며, MVP에서는 다음 광산 해금에만 쓴다. |
| 맵 강화 | `MineLevel` | 광산별 영구 레벨 0~10 (C197). 해금 직후가 레벨 0이며 보너스가 없다. 광산마다 주 보너스가 다르다. |
| 외형 피스 | `AppearancePiece` | 헤어/얼굴/의상 슬롯에 장착하는 수집 아이템. 보유하면 모든 일꾼이 함께 사용할 수 있다. |
| 도감 점수 | `CollectionScore` | 첫 외형 피스 획득 때 더하는 희귀도 점수. 일정 점수마다 모든 일꾼 수레 +1칸이다. |
| 천장 | `PityCounter` | 세 외형 가챠 풀이 공유하는 50회 전설 보장 카운터. |

## 4. 농사 → 광산 개념 매핑

| 기존(농사) | 현재(광산) | 처리 |
|---|---|---|
| 작물 `crop` | 일반 광물 `ore` | 이름·데이터 구조 교체 |
| 성장 stage 0→3 | `ReserveStage` 0→3 | 회복 로직 재활용, 채굴 시 감소 추가 |
| 수확 `harvest` | 채굴 `mine` | 광맥 stage를 감소시키고 광물을 손에 넣음 |
| 심기 `plant` | 삭제 | 광맥은 자연 회복. `load`/`unload`를 사용 |
| 드론 `Drone` | 일꾼 `Worker` | 이름 교체 |

## 5. 코드 심볼·경로 정리 원칙

| 기존 | 변경 후/원칙 | 비고 |
|---|---|---|
| `FarmTickSimulator` | `VeinTickSimulator` | 활성 광산 시뮬레이터의 공식 명칭 |
| `DroneController` | `WorkerController` | 활성 일꾼 컨트롤러의 공식 명칭 |
| `Farm/` 경로 | `Mine/` 경로로 점진 이관 | 활성 `BlockProgramController`와 모델은 Maker 검증 뒤 별도 리팩터링 |
| `farm01.map` | 초보 광산의 기존 파일명 | 파일명 변경은 Maker에서 참조 검증 후에만 수행 |
| `ore = "gold"` | 일반 금 광물 | 희귀 금은 반드시 `rare_gold`로 구분 |
| `[FarmTick]`, `[Drone]` | `[VeinTick]`, `[Worker]` | 레거시 파일의 로그를 제외하고 새 코드에는 사용하지 않음 |
