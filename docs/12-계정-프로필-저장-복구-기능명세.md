# F7-A. 계정 프로필 · 저장 · 복구 기능 명세

> D7의 계정 소유권·저장 계약을 구현 단위로 분리한다. 경제 결과는 F7-B, 프로그램 직렬화와 재시작 규칙은 F7-C, 외형 데이터는 F7-D가 정의한다. 이 명세는 어떤 기능도 세션 Depot나 클라이언트 UI를 권위 있는 저장소로 쓰지 않게 한다.

## 1. 책임과 경계

| 구성 요소 | 실행 위치 | 책임 | 금지 |
|---|---|---|---|
| `AccountProfileService` | ServerOnly, 세계 범위 | 프로필 load/save, 버전 변환, 동시 접속 잠금 | 클라이언트 값을 신뢰해 자산 변경 |
| 도메인 서비스 | ServerOnly | 유효 거래를 profile 변경으로 적용하고 저장 요청 | 직접적인 파일/저장소 접근 |
| HUD·화면 | ClientOnly | 읽기 전용 동기화 값 표시, 명시적 요청 전송 | profile 원장 변경 |

`VeinState`, 회복 경과, 특별 광맥 활성 목록, 현재 셀, 실행 스택은 저장하지 않는다. `AccountStorage`와 일꾼의 손·수레는 저장한다.

## 2. 프로필 계약

```text
AccountProfile
  schemaVersion
  currencies: Gold, Crystal, MineToken
  progress: unlockedMineIds, lastMineId, mineLevels, tutorial
  storage: normalOreCounts, rareOreCounts, autoSellSettings
  workers: owned worker records, cart upgrades, hand/cart, appearance, lastValidProgramId
  programs: library records, slot count
  appearance: owned pieces, collection score, pity counter
  rareGrowth: acquisition counts, passive levels
```

- 모든 ID는 표시 이름이나 엔티티 UUID가 아닌 안정적인 논리 ID를 쓴다.
- 수량은 음수가 될 수 없고, 알려지지 않은 필드는 버전 변환 전 백업에서 보존한다.
- 새 계정 기본값은 일꾼 1명, 골드 0, 기본 프로그램 1개, `beginner_mine` 해금이다.

## 3. 저장 및 복구 절차

1. 로그인 시 계정별 동시 접속 잠금을 획득한다. 이미 잠겼으면 “다른 기기에서 플레이 중입니다”를 표시하고 플레이를 시작하지 않는다.
2. 최신 profile을 읽어 스키마를 확인한다. 이전 버전이면 원본을 백업한 뒤 변환한다.
3. 변환/검증 성공 시 서버 메모리 원장에만 로드하고, 클라이언트에는 필요한 읽기 전용 요약만 동기화한다.
4. 판매·구매·강화·해금·외형 획득/장착·프로그램 변경은 성공 결과를 적용한 뒤 즉시 저장한다.
5. 자동 저장, 맵 이동, 종료 때도 저장한다. 종료는 동시 접속 잠금을 해제한다.

중요 저장이 실패하면 해당 거래를 완료 처리하지 않고 원장을 이전 상태로 되돌린 뒤 비용을 반환한다. 접속 중 저장 실패는 현재 플레이를 멈추지 않되 경고 상태를 남긴다.

## 4. 실패·복구 UX

- 다음 접속에서 복구 후보가 있으면 `복구`와 `포기`를 먼저 제시한다.
- 자동 재시도는 하지 않는다. `복구`를 눌렀을 때만 저장소 읽기/변환을 다시 시도한다.
- 복구 실패 원인은 내부 오류 전문 대신 사용자에게 이해 가능한 요약으로 표시하고, 서버 로그에는 profile 버전과 거래 종류를 남긴다.
- `포기`는 손상 후보만 포기한다. 정상적으로 저장된 이전 profile은 지우지 않는다.

## 5. 수용 테스트

| # | 시나리오 | 기대 결과 |
|---|---|---|
| A1 | 새 계정 시작 | 기본 profile과 초보 광산/일꾼/프로그램이 생성됨 |
| A2 | Depot 입고 뒤 재접속 | AccountStorage와 일꾼 손·수레가 복구되고 광맥 stage는 초기화됨 |
| A3 | 중요한 구매 중 저장 실패 | 구매 취소, 비용 반환, 중복 지급 없음 |
| A4 | 이전 schema profile 접속 | 원본 백업 후 변환, 유효 데이터 보존 |
| A5 | 같은 계정 두 번째 접속 | 두 번째 접속이 차단되고 첫 세션 원장은 유지됨 |
| A6 | 손상 복구 후보 | 사용자 선택 전 재시도하지 않고 복구/포기 흐름을 표시 |
