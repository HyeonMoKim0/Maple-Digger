### 0.1 이 게임이 무엇인가

**메이플 디거** — 블록 프로그램으로 일꾼을 자동화해 광물을 캐고, 판매한 돈으로 일꾼·광산·외형을 해금하는 계정 성장형 게임이다. 탑다운(RectTile) 광산 맵에서 일꾼이 `이동 / 채굴 / 적재 / 하역` 블록을 0.4초 틱마다 1개씩 실행한다. **서버가 모든 원장(광맥 상태·창고·재화)을 판정하고, 클라이언트 UI는 읽기와 요청만 한다.**

### 0.3 개발 환경

- **Maker 에디터**가 실행돼 있어야 한다. 코드는 워크스페이스 파일을 직접 편집하고, Maker가 `refresh`로 읽어들인다.
- CoreVersion은 **`26.7.0.0`** (`Environment/config`). 다르면 작업을 멈추고 확인할 것.
- 검증 루프: **파일 수정 → `refresh` → 빌드 로그 확인 → `play` → 런타임 로그·화면 확인 → `stop`**
- 이 프로젝트는 Claude Code + MSW 스킬로 작성돼 왔다. `.ui` / `.model` / `.map`은 **전용 빌더(CJS)를 경유**하며, 그 호출법은 스킬 문서에 있다. 직접 JSON을 편집하면 UUID·컴포넌트 목록 정합성이 깨진다.
- **Claude Code로 작업한다면 `.mcp.json`을 새로 만들어야 한다** — API 키가 들어 있어 저장소에 없다. 이게 없으면 Maker MCP 도구가 아예 뜨지 않는다. 나머지 AI 작업 환경(`.claude/` 스킬·훅)은 클론에 포함돼 있다. 절차: [17-Claude-인수인계.md](17-Claude-인수인계.md) **§9**.
- **Play를 돌리면 Maker가 `.ui`/`.map`/`.model`을 정규화 재저장한다.** `git status`에 안 만진 파일이 떠도 당황하지 말 것. `node tools/audit_resave.cjs`가 정규화인지 실제 변경인지 판정해 준다 — 정규화면 별도 `chore:` 커밋으로 분리한다(기능 커밋에 섞지 않는다).

### 0.5 MSW 특유의 조용한 실패 5개 — 실제로 이 프로젝트에서 다 터졌다

오류도 경고도 없이 기능이 사라지는 부류다. 발견 이력은 `docs/16`에 있다.

| 함정 | 증상 | 방지 |
|---|---|---|
| **`property <Type> x = "uuid"` 타입 불일치** | `GetComponent(Type)`이 **nil** 반환 → `if x ~= nil` 가드와 만나 기능이 조용히 사라짐. 빌드 로그에도 안 남음 | 바인딩 추가·변경 후 **`node tools/audit_bindings.cjs`** 실행. 오래된 `.ui` 엔티티는 레거시 `TextComponent`, 빌더가 만든 입력창은 `TextGUIRendererInputComponent` (D-11 3건 + D-12 5건) |
| **`patch()`가 기존 `Pivot`을 보존** | 앵커만 바꾸면 박스가 반대쪽으로 밀려나 패널 밖으로 튀어나감 | 앵커를 바꿀 때 `pivot`을 **항상 함께** 넘긴다 (D-2 작업 중 `L014` 184px 이탈) |
| **한 패널 안 앵커 모드 혼용** | `AlignmentOption=0`(중앙)과 `=3`(상단)을 섞으면 같은 행에 두려던 요소가 아래로 밀려 겹침 | 패널 내부는 **`top-center` + pivot `(0.5,1)`** 로 통일, "패널 상단에서 y px" 단일 좌표계 (D-9 7건) |
| **`TileMapMode` ↔ Body 불일치** | 엔티티가 움직이지 않거나 `[LEA-3004]` | 이 프로젝트 광산은 전부 **RectTile(=1) → `KinematicbodyComponent`** |
| **`SpriteRUID`가 빈 문자열** | 화면에 아무것도 안 보임 (오류 없음) | 렌더러를 만들면 반드시 실제 RUID를 넣는다 |

### 0.6 검증 도구의 한계 — 반드시 알아야 함

**MCP의 마우스 입력은 `ButtonComponent`를 클릭할 수 없다.** 자동으로 버튼을 눌러 회귀 테스트하는 것이 **원천적으로 불가능**하다(`docs/16` §9).

대안으로 이 프로젝트가 쓰는 방법:

1. **로직 검증**: `maker_execute_script`로 핸들러를 직접 호출한다. 예 — `_MineSelectController:OnSellSelectedClicked()`
2. **서버 규칙 검증**: `server_main` 컨텍스트에서 도메인 서비스를 직접 호출해 원장·거절을 확인한다
3. **화면 검증**: `maker_screenshot`으로 상시 표시 화면을 확인한다
4. **버튼 실클릭**: 사람이 직접 (자동화 불가)

> ✅ **오너 결정 완료 (2026-08-16, C217): 3상태 — `Idle` / `Running` / **`Stopped` 신설**, `Blocked` 는 보류.**
>
> **왜 이 결정이 필요했나.** `ProgramState` 는 2값처럼 보이지만 실제로는 **서로 다른 5가지 결말이 전부 `"Idle"` 하나로 뭉개져** 있다 — 아직 안 돌림 / 자연 완료(`FinishProgram`) / 사용자 정지(`StopProgram`) / 맵 전환 강제 정지(`StopForMapTransition`) / 서버 거절(`RequestRun` 검증 실패). 다섯 경로가 모두 `ResetExecution()` 하나로 모인다.
>
> **`Stopped` 와 `Blocked` 는 비용이 전혀 다르다** — 이것이 갈라 놓은 이유다.
>
> | 상태 | 정보 소재 | 판단 |
> |---|---|---|
> | **`Stopped`** | **이미 코드에 있다.** 위 5개 호출 지점을 구분만 하면 된다 — 로직 추가가 아니라 **분류** | **신설한다.** 블록 자동화 게임에서 제일 자주 나오는 질문이 "왜 멈췄지?" 인데 그 답이 이미 있는데도 버려지고 있다 |
> | **`Blocked`** | **없다.** "돌고는 있는데 진행 불가"(수레 가득·광맥 고갈·맵 경계)를 판정하는 로직 자체가 없다 | **보류.** 무엇을 '진행 불가'로 볼지부터 기획 결정이고 D2 §5 안전 규칙을 건드린다. 폴리싱 티켓이 기능 티켓으로 번진다 |
>
> **구현 범위**: `ResetExecution` 을 호출 맥락에 따라 `Idle` / `Stopped` 로 나눈다. `FinishProgram`(자연 완료)과 최초 상태는 `Idle`, `StopProgram`·`StopForMapTransition`·거절은 `Stopped`. F5 §5 HUD 계약에 상태값 1개 추가를 반영하고, `docs/26` §5.4 는 `status-blocked-yellow` 를 **보류로 정정**한다(업로드하지 않는다).

- 램프는 **`MineInventoryController` 가 소유**한다 (`GetWorkerStateSummary` 가 이미 상태를 읽는다). `BlockProgramController` 가 따로 들면 선택 링과 같은 이중 소유 문제가 난다 (F5 §5.3).
