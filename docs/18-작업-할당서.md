### 0.1 이 게임이 무엇인가

**메이플 디거** — 블록 프로그램으로 일꾼을 자동화해 광물을 캐고, 판매한 돈으로 일꾼·광산·외형을 해금하는 계정 성장형 게임이다. 탑다운(RectTile) 광산 맵에서 일꾼이 `이동 / 채굴 / 적재 / 하역` 블록을 0.4초 틱마다 1개씩 실행한다. **서버가 모든 원장(광맥 상태·창고·재화)을 판정하고, 클라이언트 UI는 읽기와 요청만 한다.**

### 0.3 개발 환경

- **Maker 에디터**가 실행돼 있어야 한다. 코드는 워크스페이스 파일을 직접 편집하고, Maker가 `refresh`로 읽어들인다.
- CoreVersion은 **`26.7.0.0`** (`Environment/config`). 다르면 작업을 멈추고 확인할 것.
- 검증 루프: **파일 수정 → `refresh` → 빌드 로그 확인 → `play` → 런타임 로그·화면 확인 → `stop`**
- 이 프로젝트는 Claude Code + MSW 스킬로 작성돼 왔다. `.ui` / `.model` / `.map`은 **전용 빌더(CJS)를 경유**하며, 그 호출법은 스킬 문서에 있다. 직접 JSON을 편집하면 UUID·컴포넌트 목록 정합성이 깨진다.

### 0.5 MSW 특유의 조용한 실패 5개 — 실제로 이 프로젝트에서 다 터졌다

오류도 경고도 없이 기능이 사라지는 부류다. 발견 이력은 `docs/16`에 있다.

| 함정 | 증상 | 방지 |
|---|---|---|
| **`property <Type> x = "uuid"` 타입 불일치** | `GetComponent(Type)`이 **nil** 반환 → `if x ~= nil` 가드와 만나 기능이 조용히 사라짐. 빌드 로그에도 안 남음 | 바인딩 추가·변경 후 **`node tools/audit_bindings.cjs`** 실행. 오래된 `.ui` 엔티티는 레거시 `TextComponent`, 빌더가 만든 입력창은 `TextGUIRendererInputComponent` (D-11 3건 + D-12 5건) |
| **`patch()`가 기존 `Pivot`을 보존** | 앵커만 바꾸면 박스가 반대쪽으로 밀려나 패널 밖으로 튀어나감 | 앵커를 바꿀 때 `pivot`을 **항상 함께** 넘긴다 (D-2 작업 중 `L014` 184px 이탈) |
| **한 패널 안 앵커 모드 혼용** | `AlignmentOption=0`(중앙)과 `=3`(상단)을 섞으면 같은 행에 두려던 요소가 아래로 밀려 겹침 | 패널 내부는 **`top-center` + pivot `(0.5,1)`** 로 통일, "패널 상단에서 y px" 단일 좌표계 (D-9 7건) |
| **`TileMapMode` ↔ Body 불일치** | 엔티티가 움직이지 않거나 `[LEA-3004]` | 이 프로젝트 광산은 전부 **RectTile(=1) → `KinematicbodyComponent`** |
| **`SpriteRUID`가 빈 문자열** | 화면에 아무것도 안 보임 (오류 없음) | 렌더러를 만들면 반드시 실제 RUID를 넣는다 |

### 0.6 검증 도구의 한계 — 반드시 알아야 함

**MCP의 마우스 입력은 `ButtonComponent`를 클릭할 수 없다.** 자동으로 버튼을 눌러 회귀 테스트하는 것이 **원천적으로 불가능**하다(`docs/16` §9).

대안으로 이 프로젝트가 쓰는 방법:

1. **로직 검증**: `maker_execute_script`로 핸들러를 직접 호출한다. 예 — `_MineSelectController:OnSellSelectedClicked()`
2. **서버 규칙 검증**: `server_main` 컨텍스트에서 도메인 서비스를 직접 호출해 원장·거절을 확인한다
3. **화면 검증**: `maker_screenshot`으로 상시 표시 화면을 확인한다
4. **버튼 실클릭**: 사람이 직접 (자동화 불가)

- 레벨은 **0~10**, 해금 직후 0이며 보너스 0. `AccountProfile.progress.mineLevels`에 세 맵 정수로 저장.
- **프로필 스키마 v7 → v8**. 변환 시 세 맵 모두 레벨 0으로 채운다. v8에서 함께 추가할 필드 3개:
  - `progress.mineLevels`
  - worker record의 **손 개수**(`yield` 효과가 채굴 1회에 최대 2개를 주므로 필요. 현재 `PendingOre`가 단일 문자열이라 개수를 표현하지 못한다). v7은 손에 광물이 있으면 1, 없으면 0으로 변환
  - `currencies.Crystal` (D7 §3.1이 저장 대상으로 규정했는데 필드가 없다. v7은 0으로 변환)
  - `tutorial` 객체 (F7-E §10.2). T-07이 이 필드를 쓰므로 **v8에 함께 넣는다.** v7은 `step = 0` + 모든 플래그 `false`로 변환
- 효과 4종의 계산 방식이 **각각 다르다**. §5.3을 그대로 따를 것:
  - `recovery` — 연속값 곱, 희귀 철 패시브와 **가산 합성** (C198)
  - `specialSpawn` — `max(60, floor(750 / (1 + 보너스)))`, 하한 60틱 (C200)
  - `rareChance` — 정수 백분율을 **만분율(basis point)로 승격**하고 판정도 `RandomIntegerRange(1, 10000)`으로 옮긴다. 기존 테스트 훅 `RareDropTestPercent`도 `RareDropTestBasisPoint`로 이동
  - `yield` — 확률로 같은 광물 **1개 추가 지급**(최대 2개). **희귀로 승격된 채굴에는 적용하지 않는다** (C199)
- `VeinTickSimulator`는 **매 틱 프로필을 조회하지 않는다.** 맵 진입 시와 강화 성공 시에만 네 보너스를 캐시한다.
- **화면 표기용 `@Sync` 7종을 함께 내려보낸다** — F7-B **§5.6.5**. 현재·다음 누적 보너스, `effectiveSpawnTicks`, 적용 후 `bp`, 합성 후 `recoveryMultiplier`, 다음 레벨 비용. 클라이언트가 `%`를 재계산하면 버림·만분율·하한 때문에 서버와 어긋난다(§5.6.3). T-03이 이 값들을 그대로 표시한다.
- 저장 실패 시 레벨과 비용을 **모두 이전 상태로 롤백**한다.
- 강화는 **해당 광산에 입장한 상태에서만** 요청 가능하다.

**수용 기준** — F7-B §6의 **B8 ~ B18**을 그대로 쓴다. 특히:

- [ ] B8: v7 프로필로 접속하면 v8로 변환되고 세 맵 레벨 0, 기존 값과 일꾼 손(1개)이 보존
- [ ] B9: 초보 광산 0→1 강화에 골드 30 · 돌 20 차감, `yield` +3% / 나머지 +1%
- [ ] B10: 레벨 10에서 추가 요청은 차감 없이 거절
- [ ] B12: 깊은 광산 레벨 10 + 희귀 철 10단계 → 회복 배율 `1 + 0.30 + 0.30 = 1.60`
- [ ] B13: 보석 광산 레벨 10 → 일반 광맥 130bp, 특별 광맥 650bp
- [ ] B14: 특별 광맥 대기 틱이 `floor(750 / (1 + 보너스))`, 하한 60틱
- [ ] B16~B18: `yield` 2개 지급, 희귀 승격 시 추가 지급 없음, 손 2개 상태로 재시작 시 복구

**주의**

- 이 티켓은 **프로필 스키마를 바꾼다.** 다른 티켓과 동시에 진행하면 저장 데이터가 충돌한다. 단독 진행할 것.
- B12~B14·B17은 `maker_execute_script`(`server_main`)로 자동 검증 가능하다. 광산 선택 화면의 레벨 표시는 T-03의 몫이다.
