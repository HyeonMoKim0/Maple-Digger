# D1. 메이플 디거 — 마스터 게임 디자인 문서 (GDD)

> 2026-07-12 작성. 용어는 [01-테마전환-용어집.md](01-테마전환-용어집.md) 기준.
> 이 문서는 전체 조망용이다. 시스템별 구현 상세는 D2(블록 명령)·D3(자원/인벤토리)·D4(일꾼)·D5(비주얼)에 위임한다.

## 1. 게임 한 줄 정의

**텍스트 코딩 없이, 블록 조립(또는 한국어 문장 입력)으로 일꾼의 채굴 자동화를 설계하는 탑다운 방치형 게임.**

- 플랫폼: 메이플스토리 월드, Top-down 그리드 맵 (RectTile, TileMapMode=1 — 현행 `farm01.map` 유지)
- 참조작: The Farmer Was Replaced (Python 코딩 → 블록/자연어로 진입장벽 제거)
- 타깃 경험: "내가 짠 설계대로 알아서 돌아간다"는 설계의 재미 + 방치 누적 성장 + 천재적 체감

## 2. 핵심 루프

```
[설계]  블록 조립 or 한국어 문장 입력("오른쪽 두 칸 가서 캐고 실어")
   ↓
[실행]  일꾼이 프로그램대로 틱 단위 자율 행동 (이동 → 채굴 → 운반 → 창고 저장)
   ↓
[수확]  창고에 광물 누적 (자원 증가)
   ↓
[방치]  광맥이 틱마다 매장량 회복 → 일꾼은 계속 순환 작업
   ↓
[개선]  더 효율적인 프로그램으로 개량 / 일꾼 추가 배치  → 다시 [설계]
```

루프가 굴러가는 최소 조건: 반복·조건 블록(③단계)이 있어야 "계속 순환 작업"이 성립한다. 그 전까지는 1회성 실행만 가능(현재 상태).

## 3. 시스템 구성과 책임 분리

| # | 시스템 | 실행 위치 | 담당 스크립트 | 상태 |
|:-:|---|:--:|---|:--:|
| 1 | 그리드 광산 (셀/광맥 배치) | 서버 | `farm01.map` + `VeinTickSimulator` | 프로토타입 완료(리스킨 대상) |
| 2 | 틱 기반 광맥 재생 | 서버 | `VeinTickSimulator` (구 FarmTickSimulator) | 완료(리스킨 대상) |
| 3 | 일꾼 자동화 엔진 (인터프리터) | 서버 | `WorkerController` (구 DroneController) | **D2 구현·검증 완료** |
| 4 | 블록 조립 UI | 클라 | `BlockProgramController` + `BlockProgramUI.ui` | **D2 제어 블록·정지 UI 구현 완료** |
| 5 | 자연어 → 블록 변환 | 클라 | `BlockProgramController.ParseChatCommand` | **전용 텍스트창·명시적 실행 UX 구현 완료** |
| 6 | 자원·인벤토리 | 서버(원장) + 클라(HUD) | `WorkerController` + `VeinTickSimulator` + `MineInventoryController` | **D3 구현·검증 완료** |
| 7 | 일꾼 외형·다중 배정 | 서버+클라 | `Worker.model` + 기존 컨트롤러 확장 (D4) | **D4-A 다중 배정 검증 완료 / 랜덤 외형 미착수** |
| 8 | 맵 레이아웃 데이터화 | 서버+맵 | `MineLayoutConfig` + `VeinTickSimulator` (D6) | **기획·기능 명세 완료 / 구현 미착수** |
| 9 | 비주얼·사운드 피드백 | 클라 표시 + 서버 이벤트 | marker/visual/sound controller (D5) | **기획·기능 명세 완료 / 구현 미착수** |

### 서버 ↔ 클라 경계 (RPC 계약)

```
클라 (BlockProgramController @Logic, ClientOnly)
  · 블록 조립, 자연어 파싱, 프로그램 리스트 표시        ← UI는 전부 클라
  · Run 버튼 → WorkerController:RunProgram(program)     ← @ExecSpace("Server") RPC
  · Stop 버튼 → WorkerController:StopProgram()          ← 신규 (D2)

서버 (WorkerController, VeinTickSimulator — ServerOnly)
  · 프로그램 재검증(블록 수/깊이 한도) 후 인터프리터 실행 ← 클라 입력을 신뢰하지 않음
  · 광맥 상태·자원 원장의 단일 진실 공급원
  · 결과 통지(자원 변화, 프로그램 종료)는 서버→클라 이벤트/RPC로 전달 (D3에서 확정)
```

## 6. 고정 설계 결정 (변경 시 팀 합의 필요)

1. **틱 = 0.4초, 틱당 1액션** — 참조작의 리듬. 밸런싱은 이 값을 기준으로 D3에서 수치화.
2. **인터프리터는 서버에서만 실행** — 클라는 프로그램 "편집기"일 뿐, 실행 권한 없음 (치팅 방지 + 멀티 대비).
3. **자연어 변환은 오프라인 규칙 기반** — 외부 API 의존 없음 (개발계획서의 생성형 AI 활용 계획 1번 항목과 일치).
4. **맵 모드는 RectTile(=1) 고정** — 일꾼은 `KinematicbodyComponent` 기반 셀 텔레포트 이동 유지.
5. **MVP는 1인 세션** — 광산·창고는 세션 내 단일 원장, 모든 일꾼은 한 플레이어 소유. 플레이어별 권한 분리는 범위에서 제외.
6. **PC 우선 UI** — 1920×1080 기준으로 우선 완성하며 모바일 전용 재배치는 후속 범위로 둔다.
