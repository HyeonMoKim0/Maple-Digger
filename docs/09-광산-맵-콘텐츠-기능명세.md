# F6. 광산 맵 · 콘텐츠 배치 기능 명세

> D6 구현 계약. 목표는 임시 코드 좌표를 map-authored 설정으로 바꾸고, 게임 데이터와 월드 마커를 검증 가능하게 연결하는 것이다.

## 1. 구성 요소

| 구성 요소 | 부착 위치 | 책임 |
|---|---|---|
| `MineLayoutConfig` | `farm01` 맵 엔티티 | 정적 레이아웃 설정과 marker 연결의 단일 기준 |
| `VeinTickSimulator` | `farm01` 맵 엔티티 | 시작 시 설정 검증·런타임 원장 생성·광맥/창고 API 제공 |
| `VeinMarker` | 광맥별 월드 엔티티 | D5에서 정의한 시각 상태를 해당 `VeinId`로 표시 |
| `DepotMarker` | 창고 월드 엔티티 | `DepotId`의 위치와 하역 강조 표시 |
| `WorkerController` | Worker01/02 | 맵 설정으로 검증된 시작 셀에서 시작하고 simulator API만 사용 |

`MineLayoutConfig`와 `VeinTickSimulator`는 모두 맵 스코프 Component다. Logic으로 만들지 않아 맵 전환 후 상태가 남지 않게 한다.

## 2. 정적 설정 데이터 계약

### 2.1 `MineLayoutConfig`

| 필드 | 타입 | 필수 | 설명 |
|---|---|:--:|---|
| `LayoutVersion` | integer | O | 현재 1 |
| `DepotDefinitions` | table | O | 최소 1개, MVP는 정확히 1개 |
| `VeinDefinitions` | table | O | 1개 이상 |
| `WorkerStarts` | table | O | WorkerIndex별 시작 셀 |

`DepotDefinitions` 한 항목:

```lua
{ id = "depot-main", cellX = 0, cellY = 0, markerId = "depot-main-marker" }
```

`VeinDefinitions` 한 항목:

```lua
{
  id = "vein-stone-01",
  cellX = 1, cellY = 0,
  oreType = "stone",
  initialStage = 3,
  recoverTicks = 5,
  markerId = "vein-stone-01-marker",
}
```

`WorkerStarts` 한 항목:

```lua
{ workerIndex = 1, cellX = 0, cellY = 0 }
```

`markerId`는 마커 엔티티의 논리 ID이며 UUID나 경로를 기획 데이터에 직접 저장하지 않는다. 맵의 marker entity는 같은 ID를 자신의 `VeinId` 또는 `DepotId`로 가져야 한다.

## 3. 시작 절차

1. `MineLayoutConfig`가 정적 정의를 제공한다.
2. `VeinTickSimulator:ValidateLayout(config)`가 아래의 유효성 검사를 모두 수행한다.
3. 실패가 하나라도 있으면 어떤 일꾼도 등록하지 않고, ID·필드·셀 좌표가 포함된 오류를 남긴다.
4. 통과하면 simulator는 `VeinDefinitions`을 런타임 `VeinState`로 복사하고, depot 원장과 marker의 최초 stage를 초기화한다.
5. `WorkerController.OnBeginPlay`는 자신의 WorkerIndex에 해당하는 `WorkerStarts`를 읽어 셀을 초기화한다. 모델 기본값은 레이아웃 미연결 상태에서만 디버그용으로 쓴다.
6. 이후 0.4초 Tick 순서(회복 → 등록 일꾼별 최대 1액션)는 변경하지 않는다.

## 4. 유효성 검사

| 검사 | 실패 조건 |
|---|---|
| 버전 | `LayoutVersion ~= 1` |
| ID | 빈 ID 또는 같은 종류 내 중복 ID |
| 셀 | 광맥·창고·시작점이 존재하지 않는 RectTile 셀 |
| 광맥 | `oreType` 미등록, `initialStage < 0`, `initialStage > MaxReserveStage`, `recoverTicks < 1` |
| 마커 | 정의의 markerId에 맞는 marker가 없거나 둘 이상 존재 |
| 점유 | 광맥-광맥 또는 광맥-창고의 셀 중복 |
| 창고 | MVP에서 창고 수가 1개가 아님 |
| 일꾼 | WorkerIndex 1, 2의 시작점 누락 또는 중복 WorkerIndex |

일꾼 시작점과 창고의 셀 중복은 허용한다. 이는 D6 MVP 레이아웃의 Worker01 `(0,0)`과 `depot-main`을 지원하기 위한 명시적 예외다.

## 5. 런타임 API 변경 계약

| API | 호출자 | 결과 |
|---|---|---|
| `LoadLayout(MineLayoutConfig config)` | simulator 시작 절차 | 유효한 정의를 런타임 상태로 복사 |
| `GetWorkerStart(integer workerIndex)` | WorkerController | 설정된 셀 또는 명시적 오류 |
| `GetVeinById(string id)` | marker/진단 | 읽기 전용 광맥 상태 |
| `GetMarkerById(string markerId)` | simulator | 정확히 한 marker 참조 |
| 기존 `TryMine`, `HasOre`, `IsDepot`, `AddToDepot` | WorkerController | 동작·서버 권한을 유지 |

`VeinTickSimulator.OnBeginPlay` 안의 `AddVein(1, 0, ...)` 등 개별 하드코딩 호출은 `LoadLayout` 성공 후 제거한다. 광물/창고 좌표를 별도의 상수나 UI 코드에 복제하지 않는다.

## 6. 맵 작성·배포 절차

1. `MineLayoutConfig`를 MapBuilder로 갱신한다.
2. Marker 모델을 배치하고 논리 ID를 설정한다.
3. MapBuilder 검증을 실행한다.
4. Maker refresh 후 Play를 시작한다.
5. build/runtime 로그로 `layout loaded`, 광맥·창고·일꾼 수, 각 ID의 셀을 확인한다.
6. F6 수용 테스트를 통과한 뒤에만 map 파일과 관련 모델·스크립트를 함께 커밋한다.
