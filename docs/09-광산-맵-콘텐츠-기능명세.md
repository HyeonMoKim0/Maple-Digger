# F6. 광산 맵 · 콘텐츠 배치 기능 명세

> D6 구현 계약. 정적 맵 데이터와 세션 런타임 상태를 분리하고, 세 광산 및 최대 5명 일꾼을 검증 가능하게 연결한다.
> **post-MVP**: 아래 `MineLayoutConfig` 계약은 광산 필드 레벨 1(현재) 기준이다. 레벨 2~5로 필드를 넓히는 확장은 [32-필드-확장-기획.md](32-필드-확장-기획.md) (D10) §7에서 `FieldLevelDefinitions` 필드 추가를 제안한다 — 구현 착수 시 이 문서에도 반영한다.

## 1. 구성 요소

| 구성 요소 | 부착 위치 | 책임 |
|---|---|---|
| `MineLayoutConfig` | 각 광산 맵 엔티티 | 정적 레이아웃·메타·marker 연결의 단일 기준 |
| `VeinTickSimulator` | 각 광산 맵 엔티티 | 설정 검증, 세션 광맥/특별 광맥 원장, 광맥 API |
| `VeinMarker` | 일반 광맥 월드 엔티티 | `VeinId`의 stage·광물 시각화 |
| `SpecialVeinMarker` | 동적 또는 후보 월드 엔티티 | 특별 광맥 출현 상태와 전용 연출 |
| `DepotMarker` | Depot 월드 엔티티 | Depot 위치 및 하역 강조 |
| `WorkerController` | 각 일꾼 | 설정된 WorkerIndex 시작점, simulator API 호출 |

모두 맵 스코프 Component로 취급한다. 계정 데이터·광산 해금·강화는 별도 계정 서비스가 제공하며, 이 구성 요소가 직접 저장하지 않는다.

## 2. `MineLayoutConfig` 데이터 계약

| 필드 | 타입 | 필수 | 설명 |
|---|---|:--:|---|
| `LayoutVersion` | integer | O | 현재 2 |
| `MineId` | string | O | `beginner_mine`/`deep_mine`/`gem_mine` |
| `DepotDefinitions` | table | O | 정확히 1개 |
| `VeinDefinitions` | table | O | 일반 광맥 1개 이상 |
| `WorkerStarts` | table | O | WorkerIndex 1~5 시작 셀 |
| `SpecialVeinCandidates` | table | O | 특별 광맥 후보 셀/구역 |

일반 광맥 정의 예:

```lua
{ id = "vein-iron-01", cellX = 8, cellY = 1, oreType = "iron", initialStage = 3,
  recoverTicks = 10, markerId = "vein-iron-01-marker" }
```

특별 광맥 후보 예:

```lua
{ id = "special-slot-01", cellX = 9, cellY = 2, markerId = "special-slot-01-marker" }
```

`markerId`는 UUID·엔티티 경로가 아닌 논리 ID다. 맵 marker는 같은 ID를 자신의 ID property로 보유해야 한다.

## 3. 시작·전환 절차

1. 선택 광산의 `MineLayoutConfig`를 읽고 `ValidateLayout`을 실행한다.
2. 검증이 실패하면 일꾼을 등록하지 않고 ID·필드·좌표를 로그에 남긴다.
3. 통과하면 일반 광맥 정의를 세션 `VeinState`로 복사하고 특별 광맥 스케줄을 초기화한다.
4. `WorkerController`는 WorkerIndex에 맞는 시작 셀을 읽는다. 활성 일꾼 수는 계정 소유 수(1~5)만큼이다.
5. 0.4초 틱은 회복 → 특별 광맥 스폰 판정 → 등록 일꾼별 최대 1액션 순으로 처리한다.
6. 맵 전환은 모든 worker 실행을 먼저 정지하고, 새 맵 런타임을 생성한다. 새 맵에서는 자동 실행하지 않는다.

## 4. 유효성 검사

| 검사 | 실패 조건 |
|---|---|
| 버전/맵 | 미지원 `LayoutVersion`, 빈·중복 `MineId` |
| ID | 빈 ID 또는 같은 종류 안의 중복 ID |
| 셀 | Depot·일반 광맥·시작점·특별 후보가 존재하지 않는 RectTile 셀 |
| 광물 | `stone`/`iron`/`gold` 외 `oreType`, stage 범위 밖, `recoverTicks < 1` |
| marker | 정의 markerId의 marker가 0개 또는 2개 이상 |
| 점유 | 일반 광맥끼리, 일반 광맥과 Depot의 셀 중복 |
| Depot | 정확히 1개가 아님 |
| 시작점 | WorkerIndex 1~5 누락·중복. **셀 점유는 검사하지 않는다** — 아래 정정 참조 |
| 특별 후보 | 일반 광맥/Depot와의 셀 중복 또는 후보 ID 중복 |

> **정정 (2026-08-14, T-11) — 시작 셀의 점유 검사는 존재하지 않는다.**
>
> 이 표의 시작점 행은 원래 *"Depot와의 겹침만 예외 허용"* 이라 적혀 있었다. 그 문구는 "시작 셀이 광맥과 겹치면 검증 실패"를 함의하지만, **`VeinTickSimulator.ValidateLayout` 의 시작점 검사는 실제로 네 가지만 본다** — `workerIndex` 존재 · 1~5 범위 · `workerIndex` 중복 · `IsWalkableCell`. **셀 점유(광맥·Depot·특별 후보와의 겹침)는 전혀 검사하지 않는다.** 광맥끼리의 중복과 광맥↔Depot 중복만 검사가 있다(위 두 행).
>
> **그래서 시작 셀은 광맥 셀 위에 둘 수 있고, T-11 이 실제로 그렇게 뒀다** (초보 광산, 2026-08-14 오너 승인). 근거는 배치 제약이다 — 초보 광산의 광맥 4개가 서로 붙어 있어 두 광맥의 서쪽 앞칸이 다른 광맥 셀이고, 광맥 칸을 피하면 5명 중 1명만 전용 광맥을 받는다. 일꾼은 발밑 광맥이 아니라 **한 걸음 오른쪽**의 광맥을 캐므로 동작상 충돌이 없다.
>
> 이 문서를 코드에 맞춰 정정한 것이며 코드를 문서에 맞춘 것이 아니다. **점유 검사를 넣고 싶다면 그건 별도 결정**이고, 넣는 순간 T-11 의 초보 광산 배치가 검증 실패로 바뀐다.
>
> **후속 (2026-08-21, 초보 광산 10×10 확장)**: 광맥 6개 분산 재배치로 **초보 광산도 광맥 위 시작이 전부 해소됐다** (시작 셀 5개 전원 전담 광맥의 서쪽 앞칸, `docs/18` T-11 배치표 갱신본). 현재 세 맵 어디에도 광맥 위 시작은 없다. 점유 검사를 넣는 결정은 이제 기존 배치와 충돌하지 않지만, 여전히 별도 결정이다.

## 5. 런타임 API 계약

| API | 호출자 | 결과 |
|---|---|---|
| `LoadLayout(config)` | 맵 시작 | 유효한 정적 정의를 세션 상태로 복사 |
| `GetWorkerStart(workerIndex)` | WorkerController | 해당 시작 셀 또는 명시적 오류 |
| `TryMine`, `HasOre`, `IsDepot`, `AddToDepot` | WorkerController | 서버 권한의 기존 운반 결과 |
| `GetVeinById`, `GetMarkerById` | marker/진단 | 읽기 전용 일반 광맥/marker 조회 |
| `TrySpawnSpecialVeins` | simulator | 시간·최대 수를 지키며 1~2개 생성 |
| `GetSpecialVeinState` | HUD/marker | 현재 활성 특별 광맥의 읽기 전용 목록 |

특별 광맥은 한 번의 스폰에서 최대 2개, 동시 최대 3개다. 세션 종료·맵 이탈 때 제거하며 계정 저장 대상이 아니다.
