# D5. 비주얼 · 사운드 폴리싱 기획서 (⑤b)

> 2026-07-26 초안. 기준 문서: D0 용어집, D1 마스터 GDD, D3 자원·인벤토리, D4 일꾼 캐릭터.  
> 대상: PC 1920×1080 우선 MVP. 모바일 재배치는 별도 UX 기획에서 다룬다.

## 1. 목표

플레이어가 화면을 보는 것만으로 **광맥의 채굴 가능 상태**, **일꾼의 현재 행동**, **창고 누적 성과**를 이해하게 만든다. 장식은 정보를 가리는 방향으로 쓰지 않는다.

목표 경험은 다음 세 가지다.

1. 광맥은 차오르고, 캐면 비어 보인다.
2. 일꾼은 명령대로 움직이고 채굴·적재·하역한다.
3. 창고 수치가 늘어나는 순간이 자동화 설계의 보상으로 느껴진다.

## 2. 고정 결정

| 항목 | 결정 |
|---|---|
| 미술 톤 | 밝고 읽기 쉬운 메이플풍 광산. 배경은 저채도, 상호작용 대상은 명확한 윤곽과 대비를 사용한다. |
| 정보 우선순위 | 광맥 상태 → 일꾼 행동 → 창고 증가 → 장식 순서. |
| 광맥 상태 표현 | 색상만 쓰지 않는다. 광석의 크기·균열·반짝임을 함께 바꿔 0~3단계를 구분한다. |
| 기존 일꾼 | D4-B 전까지 현재 Worker01/02 스프라이트와 Worker02 색상 틴트를 임시 식별 수단으로 유지한다. |
| 사운드 | 짧은 효과음 중심. 반복 틱마다 과도하게 겹치지 않도록 같은 종류의 재생 간격을 제한한다. |
| 게임 규칙 | 비주얼·사운드 시스템은 광맥 매장량, 수레, 창고의 원장을 소유하거나 변경하지 않는다. |

## 3. 화면·오브젝트 아트 방향

### 3.1 광산 월드

| 대상 | 기본 표현 | 상태 변화 | 필수 판독 정보 |
|---|---|---|---|
| 바닥 타일 | 어두운 암반 바탕 + 이동 가능한 길의 약한 패턴 | 없음 | 이동 가능한 셀의 경계가 과도하게 드러나지 않되 길은 읽혀야 함 |
| 광맥 | 바위 안에 박힌 광석 | §4의 0~3단계 교체 | 매장량, 광물 종류 |
| 창고 | 목재 상자/광차 형태의 고정 시설 | 하역 직후 짧은 반짝임 | 하역 위치 |
| 일꾼 | 상시 식별 가능한 실루엣 | 이동·채굴·싣기·내리기 반응 | 누구인지, 지금 무엇을 하는지 |
| 선택 일꾼 | 발밑 링 또는 얇은 테두리 | 선택 변경 시 0.2초 강조 | 블록 편집기·HUD의 대상과 동일함 |

### 3.2 UI

- `BlockProgramUI`: 기존 버튼의 기능 구분을 유지하고, 실행 중인 대상 일꾼과 Run/Stop 상태를 가장 먼저 읽히게 한다.
- `MineHUD`: 창고 돌 수량은 항상 보이고, 선택 일꾼의 손·수레만 보인다. 공용 창고와 개인 수레를 같은 색 의미로 표현하지 않는다.
- 인벤토리 팝업: MVP는 돌 1종이라도 다종 확장을 전제해 행 단위 목록 구조를 유지한다.
- 월드 오브젝트를 가리는 큰 안내문은 사용하지 않는다. 실패 피드백은 기존 블록 패널의 피드백 줄을 우선 사용한다.

## 4. 광맥 상태·행동 연출

### 4.1 매장량 4단계

| ReserveStage | 상태명 | 시각 | 사운드/효과 |
|:--:|---|---|---|
| 0 | 고갈 | 광석이 보이지 않는 균열 바위, 반짝임 없음 | 채굴 실패 시 약한 둔탁음만 1회 |
| 1 | 미량 | 작은 광석 1개, 약한 윤곽 | 채굴 시 작은 파편 1~2개 |
| 2 | 보통 | 중간 광석 덩어리, 희미한 광택 | 채굴 시 파편 + 짧은 금속음 |
| 3 | 만재 | 큰 광석 군집, 가장 분명한 반짝임 | 채굴 시 파편 + 강조된 금속음 |

- 회복은 0→1, 1→2, 2→3 순으로 단계가 한 번씩만 바뀌며, 단계 상승마다 0.25초 이내의 짧은 반짝임을 낸다.
- 광석 종류가 늘어나면 실루엣은 동일하게 두고 광석 색·작은 아이콘만 달리한다. 희귀도는 색상만으로 판별하지 않는다.

### 4.2 일꾼 행동

| 이벤트 | 월드 연출 | UI/사운드 |
|---|---|---|
| 이동 | 0.4초 틱 안에서 다음 셀로 명확히 이동, 발밑 먼지 소량 | 기본 이동음 없음 |
| 채굴 성공 | 곡괭이/팔 동작 또는 0.15초 스쿼시, 광맥 파편 | 채굴음 1회 |
| 채굴 실패 | 과장 없는 멈춤 | 실패음은 선택 일꾼에만, 0.8초 재생 제한 |
| 싣기 | 손 아이콘이 수레로 이동하는 짧은 효과 | 적재음 1회 |
| 하역 | 수레→창고 방향의 작은 광석 이동 + 창고 반짝임 | 하역음 1회, HUD 수치 강조 |
| 선택 변경 | 발밑 링이 새 대상에 표시 | 효과음 없음 |

## 5. 사운드 설계

| Cue ID | 트리거 | 길이/성격 | 중복 제어 |
|---|---|---|---|
| `mine_hit` | 채굴 성공 | 0.15~0.35초, 돌/금속 타격 | 같은 일꾼 0.25초 이내 재생 금지 |
| `mine_empty` | 고갈·광맥 없음 채굴 | 0.1~0.2초, 낮은 둔탁음 | 선택 일꾼만, 0.8초 제한 |
| `cart_load` | 싣기 성공 | 짧은 적재음 | 같은 일꾼 0.25초 제한 |
| `depot_unload` | 하역 성공 | 보상감 있는 상자/동전 계열 | 같은 틱에는 1회만 |
| `vein_recover` | 광맥 단계 상승 | 매우 약한 반짝임 | 화면에 보이는 광맥만, 1초 제한 |
| `ui_convert` / `ui_run` / `ui_stop` | UI 성공 행동 | 짧은 인터페이스 효과 | 버튼 연타 시 0.15초 제한 |

- BGM은 구현 1차 범위에서 제외한다. `mine_hit` 등 핵심 상호작용이 충분히 읽히는지 확인한 뒤 30~60초 반복 루프를 추가한다.
- 효과음은 클라이언트에서 재생하며, 서버는 재생 요청이 아니라 이미 일어난 게임 이벤트만 동기화한다.

## 6. 자산 목록과 승인 기준

RUID는 이 문서에서 임의로 고정하지 않는다. 후보를 검색·미리보기로 승인한 뒤 아래 표의 `승인 RUID` 열을 채운다.

| 자산군 | 수량 | 용도 | 승인 기준 |
|---|:--:|---|---|
| 광산 바닥/벽 타일 | 1세트 이상 | `farm01` 배경·길 | 광맥·일꾼과 명도 충돌이 없고 반복 타일 이음새가 눈에 띄지 않음 |
| 돌 광맥 상태 스프라이트 | 4 | stage 0~3 | 100% 크기에서 네 상태가 구분됨 |
| 광맥 회복/채굴 파편 | 2~3 | 상태 전환·채굴 | 0.4초 틱을 가리지 않고 0.3초 내 종료 |
| 창고 스프라이트 | 1 + 강조 1 | Depot | 어느 방향에서 보아도 하역 위치로 인식됨 |
| 일꾼 임시 행동 연출 | 4 | move/mine/load/unload | 현재 스프라이트가 정적이어도 위치·파편 효과로 행동 구분 가능 |
| UI 아이콘 | 돌, 수레, 손, 실행 상태 | HUD·패널 | 24px 이상에서 의미가 분명함 |
| 효과음 | 7 cue | §5 | 동시 재생 때도 피로감·왜곡이 없음 |

## 7. 범위와 의존성

- 포함: 광맥 단계 표현, 창고·일꾼 상호작용 피드백, HUD 강조, 효과음, 자산 RUID 승인표.
- 제외: 일꾼 랜덤 아바타 조합과 획득 연출(D4-B), 상점/판매, 모바일 전용 UI, BGM 정식 제작.
- D6 광산 맵·콘텐츠 기획서가 광맥·창고의 위치 및 식별자 단일 기준을 제공한다. D5는 그 식별자를 사용해 보이는 요소만 연결한다.
