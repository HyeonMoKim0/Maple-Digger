# F7-C. 프로그램 라이브러리 · 세션 기능 명세

> D2의 중첩 블록 인터프리터와 D4/D7의 계정 공용 설계도를 연결한다. 실행 엔진의 검증 규칙은 D2가 소유하고, 이 명세는 보관·선택·재접속·맵 전환의 수명 경계를 정의한다.

## 1. 프로그램 레코드와 소유권

```text
ProgramRecord
  programId, name, blockTree, dataVersion, updatedAt, lastValidation
WorkerProgramReference
  workerId, lastValidProgramId
```

- 라이브러리는 계정 공용이며 초기 3개, 최대 20개 슬롯이다. 슬롯 구매 비용은 직전 비용의 1.2배다.
- 이름은 한글/영문/숫자 최대 12자이며, `programId`는 이름과 별개로 안정적이다.
- MVP 관리 기능은 저장, 이름 변경, 복제, 삭제다. 블록 구조와 데이터 버전도 함께 저장한다.
- 클라이언트의 선검증은 UX용이다. 서버 `WorkerController`가 최종 검증에 통과한 프로그램만 마지막 유효 프로그램으로 기록한다.

## 2. 실행 절차

1. 플레이어가 대상 일꾼과 프로그램 내용을 확인한다.
2. 클라이언트가 실행 요청을 보내고 서버가 D2 블록 수·깊이·무한 반복 규칙을 재검증한다.
3. 성공하면 대상 일꾼의 기존 실행을 멈추고 새 프로그램을 처음부터 시작한다.
4. 실패하면 실행 상태와 마지막 유효 프로그램을 바꾸지 않고, 문제와 수정안을 UI에 표시한다.

프로그램 실행 중의 frame/현재 인덱스는 저장하지 않는다.

## 3. 맵 전환과 재접속

| 상황 | 프로그램 처리 |
|---|---|
| 새 광산 전환 | 모든 일꾼을 정지하고 새 맵에서는 명시적 Run 대기 |
| 정상 종료 | 마지막 유효 프로그램 참조만 계정에 저장 |
| 재접속 | 마지막 광산 진입 후 HUD 상태를 잠시 보여 주고, 각 보유 일꾼의 마지막 유효 프로그램을 처음부터 자동 실행 |
| 저장 프로그램 무효화 | 자동 실행하지 않고 Idle 및 수정안 표시 |

재접속 자동 실행은 F7-A의 profile 복구와 F6의 새 맵 초기화가 끝난 뒤에만 시작한다. 맵 전환의 수동 실행 규칙은 재접속 규칙보다 우선한다.

## 4. UI 요구사항

- **편집기 버퍼는 일꾼별이다 (2026-08-28 신설, `docs/16` §88).** 일꾼 탭을 바꾸면 그 일꾼의 조립 상태(블록·열린 제어 블록 스택·`횟수 ×N` 프리셋)가 그대로 복원된다. 그 일꾼 탭을 처음 여는 경우에만 서버의 마지막 유효 프로그램으로 1회 채운다(§3 재접속 규칙과 같은 축이며, 튜토리얼 1회차 중에는 채우지 않는다).
  - 버퍼 자체는 **클라이언트 메모리**다 — 로그아웃하면 사라지고, 계정에 남는 것은 §1 의 `lastValidProgramJson`(실행을 통과한 것)뿐이다.
  - **`[전체복사]`** 는 현재 일꾼의 블록을 나머지 보유 일꾼 전원의 버퍼로 **깊은 사본**으로 복사한다(실행은 하지 않는다). 라이브러리의 저장·불러오기와는 별개 경로이며, 슬롯을 소모하지 않는다.
- 라이브러리 화면은 슬롯 사용량, 이름, 마지막 검증 결과, 수정일과 대상 일꾼을 명확히 표시한다.
- Run 전에는 대상 일꾼과 중첩 블록 내용을 보여 준다.
- HUD는 최대 5명 `Idle`/`Running`/`Blocked`/`Stopped` 상태를 표시하고, 상세 손·수레는 선택 일꾼을 우선한다.
- 손상/무효 프로그램의 원본은 자동 수정하거나 조용히 덮어쓰지 않는다.
