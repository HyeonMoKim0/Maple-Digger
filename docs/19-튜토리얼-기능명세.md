## 1. 범위와 목표

새 플레이어에게 **블록 자동화의 기본 루프**를 8단계로 가르친다. `이동 → 채굴 → 적재 → 하역 → 반복 → 조건 → 판매 → 일꾼 구매` (C66).

- 포함: 단계 정의·완료 판정·강제 흐름·안내 UI·진행도 저장·스킵/다시 보기·보상·튜토리얼 전용 규칙 완화
- 제외: ~~자연어 변환창 교육~~ (**자연어 입력 자체가 T-14 로 MVP 에서 제거됐다** — 2026-08-18, `docs/28`. §9.3 힌트도 함께 폐지), 외형·맵 강화·희귀 컬렉션 교육(MVP 튜토리얼 범위 밖)

**설계 원칙**: 튜토리얼은 **게임 규칙을 우회하지 않는다.** 플레이어가 실제 블록을 조립해 실제 서버 실행으로 단계를 통과한다. 예외는 §8에 명시한 세 가지 완화뿐이다.

## 3. 완료 판정 — 기존 `@Sync` 상태 변화로 한다

**F5 §2.2의 `VisualEventSequence` / `VisualEventKind`는 아직 구현돼 있지 않다.** 튜토리얼이 그것을 기다리면 T-04(F5 연출)에 종속된다. 대신 **`WorkerController`와 `AccountProfileService`가 이미 내려보내는 `@Sync` 값의 변화**로 판정한다. 8단계 전부 이 방식으로 판정 가능함을 확인했다.

| 단계 | 판정 신호 (`@Sync` 변화) |
|:-:|---|
| 1 이동 | `WorkerController.CellX` 또는 `CellY`가 변한다 |
| 2 채굴 | `PendingOre`가 `""` → 광물 키로 변한다 |
| 3 적재 | `CartCount`가 증가한다 |
| 4 하역 | `CartCount`가 `> 0` → `0`이 되고 동시에 `AccountProfileService.Stone`이 증가한다 |
| 5 반복 | 프로그램에 `repeat` 블록이 있고 `ProgramState`가 `Running` → `Idle`로 완주한다 |
| 6 조건 | 프로그램에 `if` 블록이 있고 `ProgramState`가 `Running` → `Idle`로 완주한다 |
| 7 판매 | `AccountProfileService.Gold`가 증가하고 `LastTransactionMessage`가 판매 성공 문구다 |
| 8 일꾼 구매 | `OwnedWorkerCount`가 증가한다 |

**5·6단계의 보강**: 상태 변화만으로는 "빈 반복을 넣고 완주"도 통과된다. 클라이언트는 자기가 조립한 프로그램 트리를 알고 있으므로, **Run 직전에 해당 제어 블록이 body를 갖고 있는지 선검증**하고 아니면 안내를 다시 띄운다(§5 실패 처리와 같은 경로).

> 클라이언트 판정이지만 **보상 지급과 진행도 저장은 서버가 확정**한다(§10). 클라이언트는 "단계 통과"를 서버에 요청하고, 서버가 같은 `@Sync` 값으로 재검증한 뒤 기록한다. 클라이언트 판정만 신뢰하면 진행도를 위조할 수 있다.

## 4. 8단계 정의

기준 맵은 **초보 광산**(`farm01`). Depot·일꾼 시작점 `(0,0)`, 돌 광맥 `(1,0)` `(2,0)` `(2,-1)` `(3,-1)`.

| # | 단계 | 활성(잠금 해제) 버튼 | 목표 프로그램 | 안내 문구(초안) |
|:-:|---|---|---|---|
| 1 | 이동 | `동 E`, `실행` | `E` | "일꾼을 오른쪽으로 한 칸 보내 봐요. `동 E`를 누르고 `실행`을 누르세요." |
| 2 | 채굴 | `채굴 M`, `실행` | `M` | "발밑에 돌 광맥이 있어요. `채굴 M`으로 캐 봅시다." |
| 3 | 적재 | `적재 L`, `실행` | `L` | "손에 든 돌을 수레에 실어요. `적재 L`을 누르세요." |
| 4 | 하역 | `서 W`, `하역 U`, `실행` | `W, U` | "창고는 시작 자리예요. `서 W`로 돌아가서 `하역 U`로 내리면 창고에 쌓입니다." |
| 5 | 반복 | `반복 추가`, `횟수`, `동 E`, `채굴 M`, `끝 ]`, `실행` | `R×2 [ E, M ]` 형태 | "같은 일을 여러 번 시키려면 `반복 추가`로 묶어요. 안에 블록을 넣고 `끝 ]`으로 닫습니다." |
| 6 | 조건 | `IF 추가`, `조건 선택`, `채굴 M`, `끝 ]`, `실행` | `IF(광물 있음) [ M ]` 형태 | "광물이 있을 때만 캐게 하려면 `IF 추가`를 써요." |
| 7 | 판매 | `광산 선택`, `판매`, `돌`, `1`/`10`/`전량`, `선택 수량 판매` | — | "창고의 돌을 팔아 골드를 벌어요. `광산 선택 → 판매`로 들어갑니다." |
| 8 | 일꾼 구매 | `광산 선택`, 일꾼 구매 버튼 | — | "골드로 두 번째 일꾼을 고용하면 두 배로 캘 수 있어요." |

**단계 진입 시 상태 정리**: 매 단계 시작에서 프로그램을 비우고(`OnClearClicked` 상당) 일꾼을 `Idle` + 시작 셀로 되돌린다. 앞 단계의 잔여 상태가 다음 단계 판정을 오염시키지 않게 한다.

**4단계의 전제**: 1~3단계로 일꾼이 `(1,0)`에 있고 수레에 돌 1개가 있다. 3단계 종료 시 이 상태를 유지한 채 4단계로 넘어간다(즉 4단계만 예외적으로 시작 셀 복귀를 하지 않는다). 이 예외를 구현 시 명시적으로 처리한다.

## 5. 강제 흐름과 실패 처리

### 5.1 버튼 잠금과 dim (결정 2·5)

- 튜토리얼 활성 중에는 **§4 표의 "활성 버튼" 외 모든 조작 버튼을 잠근다.**
- 잠금 = `ButtonComponent.Enable = false`
- dim = 같은 엔티티의 `SpriteGUIRendererComponent.Color` 알파를 **0.35**로 낮춘다
- **원래 색을 반드시 보관**한다. 튜토리얼 시작 시 대상 버튼들의 `Color`를 캐시하고, 단계 전환·종료·스킵 시 캐시값으로 원복한다. 캐시 없이 고정값으로 원복하면 팔레트 색이 뭉개진다.
- 잠금 대상 목록: 편집기 팔레트 12종 + `실행`/`정지`/`초기화`/`변환` + 워커 탭 5개 + `광산 선택` 열기 버튼 + 인벤토리 버튼 + 패널 접기 토글.
- **패널 접기 토글은 잠그지 않는다** — 접힌 상태에서 튜토리얼 안내만 남으면 진행이 불가능하므로, 튜토리얼 중에는 패널을 펼친 상태로 고정하고 토글 자체를 잠근다.

### 5.2 실패 판정과 자동 되돌리기 (결정 3)

다음 중 하나면 그 단계를 **실패**로 보고 되돌린다.

| 실패 조건 | 예 |
|---|---|
| 프로그램이 완주했으나 판정 신호가 오지 않음 | 2단계에서 광맥 없는 셀에서 `채굴 M` → `PendingOre`가 그대로 |
| 서버가 프로그램을 거부 | `program rejected` (블록 수·깊이·무한 반복 위반) |
| 5·6단계 선검증 실패 | 제어 블록에 body가 없음 |
| 일꾼이 경계에 막힘 | `blocked` 상태로 목표를 달성하지 못함 |

되돌리기 동작:

1. 일꾼 프로그램 정지 (`StopProgram`)
2. 프로그램 목록 초기화
3. 일꾼을 **해당 단계의 시작 상태**로 복귀 (셀·손·수레). 4단계는 §4의 예외 상태로 복귀
4. 안내 문구를 실패 사유를 덧붙여 다시 표시 — 예 "여기엔 광맥이 없어요. `동 E`로 한 칸 옮긴 뒤 다시 캐 봅시다."
5. 진행도는 **줄이지 않는다.** 같은 단계를 다시 시도한다

**신규 서버 API 필요**: `WorkerController:ResetToTutorialState(cellX, cellY, hand, cartCount)` — 서버 권위로 일꾼을 지정 상태로 되돌린다. 클라이언트가 직접 셀·손·수레를 바꾸면 안 된다.

### 6.2 툴팁 배치 규칙

대상 버튼의 `UITransformComponent`에서 화면 좌표를 읽어 **버튼의 빈 쪽**에 붙인다.

- 대상이 화면 **좌측 절반**(편집기 패널 영역, `x < 0`)이면 툴팁을 버튼 **오른쪽**에, 화살표는 왼쪽을 가리킨다
- 대상이 화면 **우측 절반**(HUD·광산 선택 영역)이면 툴팁을 버튼 **왼쪽**에, 화살표는 오른쪽을 가리킨다
- 툴팁이 화면 밖으로 나가면 위/아래로 밀어 넣는다. **화면 경계를 넘지 않는 것이 배치 규칙보다 우선**한다
- 툴팁은 F5 §6.2의 계층에서 **토스트보다 위, 차단 오버레이보다 아래**에 둔다 → `GroupOrder = 30`

### 6.3 진행도

툴팁 안에 `3 / 8` 형태로 표시한다(결정 6). 단계 이름은 표시하지 않는다 — 툴팁 문구가 이미 무엇을 할지 말해 준다.

## 7. 보상 (결정 10)

D7 §8.1의 첫 테스트 제안값 **골드 20 · 크리스탈 25 · 기본 프로그램 1개**를 다음처럼 나눈다.

| 시점 | 지급 | 근거 |
|---|---|---|
| 4단계(하역) 완료 | 크리스탈 **5** | 첫 루프를 완주한 보상. "재화가 쌓인다"를 체감시킨다 |
| 6단계(조건) 완료 | 크리스탈 **5** | 제어 블록 두 개를 배운 보상 |
| 8단계 완료 | 골드 **20** + 크리스탈 **15** + 기본 프로그램 1개 | 일괄 |

합계가 D7의 골드 20 · 크리스탈 25와 일치한다. **모든 지급은 서버가 확정하고 즉시 저장**한다(F7-A §3.3의 "중요 변경 즉시 저장").

**기본 프로그램 1개**는 프로그램 라이브러리에 저장되는 `ProgramRecord`다. 내용은 4단계에서 배운 왕복 루프를 반복으로 감싼 것으로 제안한다: `R∞ [ E, M, L, W, U ]`. 이름은 `기본 왕복`.

## 8. 튜토리얼 전용 규칙 완화

튜토리얼이 성립하려면 **정상 게임 규칙 3개를 완화**해야 한다. 모두 `tutorial.completed == false`인 동안만 적용하고, 완료 즉시 해제한다.

| # | 완화 | 이유 |
|:-:|---|---|
| C1 | **일꾼 2 가격 인하** (결정 11) | 정상가 60골드는 튜토리얼로 캔 돌로 살 수 없다 |
| C2 | **해금 보호 수량 면제** | 깊은 광산 해금 필요량 **돌 120**이 기본 보호 수량이라, 돌 몇 개로는 **판매 자체가 거부된다**(F7-B §2, 실측 확인). 7단계가 성립하지 않는다 |
| C3 | **희귀 광물 드롭·특별 광맥 스폰 억제** | 배우는 중에 예외 연출이 끼면 인지 부하가 크고, 희귀 판매 잠금 규칙까지 설명해야 한다 |

**C2가 없으면 7단계가 불가능하다.** 이건 선택이 아니라 필수다. 대안으로 7단계에서 `보호분 포함 전환`을 가르치는 방법이 있으나, 8단계 순서(C66)에 없는 개념을 끼워 넣는 것이므로 채택하지 않는다.

완화 값과 파급은 §11의 미결 사항에서 확정한다.

## 9. 스킵 · 다시 보기

### 9.1 스킵

- `건너뛰기` 버튼은 모든 단계에서 노출한다.
- 누르면 확인 팝업 → 승인 시 **튜토리얼을 종료하고 버튼 잠금·dim을 원복**한다.
- 스킵은 `tutorial.completed = false`, `tutorial.skipped = true`, `tutorial.step = <스킵한 단계>`로 저장한다.
- **스킵해도 §7의 이미 받은 중간 보상은 회수하지 않는다.** 완료 일괄 보상은 지급하지 않는다.
- **§8의 완화 C1~C3는 스킵 시 즉시 해제**한다. 스킵 후 인하 가격으로 일꾼을 사는 악용을 막는다.

### 9.2 다시 보기 (결정 8·9)

- 진입점은 **광산 선택 화면(`MineSelectUI/SelectPanel`)의 `튜토리얼 다시 보기` 버튼**이다(결정 9). C202의 IA와 일치한다.
- 누르면 **처음부터 / 이어서** 를 선택하는 팝업을 띄운다(결정 8). `tutorial.step`이 1이거나 완료 상태면 선택지 없이 처음부터 시작한다.
- 다시 보기에서는 **§7 보상을 다시 지급하지 않는다**(`tutorial.rewardsClaimed` 플래그로 판정). §8 완화도 적용하지 않는다 — 이미 정상 플레이 중이므로 규칙을 흔들면 안 된다.
- 따라서 다시 보기의 7·8단계는 **정상 규칙**을 따른다. 자원이 부족하면 그 단계에서 "골드가 부족해요"를 안내하고 건너뛸 수 있게 한다.

## 10. 책임 분리와 저장

### 10.1 구성 요소

| 구성 요소 | 실행 위치 | 책임 | 금지 |
|---|---|---|---|
| `TutorialService` | ServerOnly, 계정 | 단계 통과 **재검증**, 진행도 저장, 보상 지급, §8 완화 플래그 제공 | UI 조작 |
| `TutorialController` | ClientOnly, `@Logic` | 단계 안내·툴팁 배치·버튼 잠금/dim·판정 신호 감시·통과 요청 | 원장 변경, 진행도 자체 확정 |

| `EconomyService` / `ProgressionService` | ServerOnly | §8 완화를 **서버 판정에 반영**(가격·보호 수량) | — |

### 10.2 저장 스키마 (결정 7)

프로필에 `tutorial` 객체를 추가한다. **프로필 스키마 v8에 함께 넣는다** — v8은 T-02(맵 강화)가 담당하므로 그 티켓에 이 필드를 추가한다.

```text
tutorial = {
  step = 0,              -- 0 = 미시작, 1~8 = 진행 중 단계, 9 = 완료
  completed = false,
  skipped = false,
  rewardsClaimed = false, -- 완료 일괄 보상 수령 여부
  midRewards = { s4 = false, s6 = false },  -- 중간 크리스탈 지급 여부
}
```

- **단계 통과마다 즉시 저장**하고, 튜토리얼 종료(완료·스킵)에서도 저장한다(결정 7).
- v7 프로필은 `step = 0`, 모든 플래그 `false`로 변환한다. 즉 기존 개발 프로필은 튜토리얼을 처음부터 보게 된다.
- 저장 실패 시 F7-A §3.3대로 보상 지급을 취소하고 진행도를 되돌린다.

### 10.3 새 계정의 첫 진입

D7 §10.2 **P1**(새 계정: 일꾼 1명·골드 0·기본 프로그램 1개로 초보 광산 시작)과 **P2**(튜토리얼 완료)를 연결한다. `tutorial.step == 0`이면 초보 광산 진입 직후 튜토리얼을 자동 시작한다.

## 11. 미결 사항 — 확정 필요

### 11.1 확정 (2026-07-30, D8 C204)

| # | 항목 | 확정 |
|:-:|---|---|
| **U1** | 튜토리얼 중 일꾼 2 가격 (완화 C1) | **10골드.** 7단계에서 돌 10개를 팔면 10골드가 되어 8단계가 성립한다. 튜토리얼 완료·스킵 시 정상가 60으로 즉시 복귀한다 |

### 11.2 확정 (2026-08-07, C213)

> 원래 "구현 시 확정하는 제안"이었으나 **2026-08-07 오너가 제안값 그대로 전부 확정**했다. **이로써 F7-E의 미결은 0건이다** — T-07 담당자는 아래를 그대로 구현한다.

| # | 항목 | 확정 |
|:-:|---|---|
| **U3** | 7단계에 필요한 돌을 어떻게 확보하나 | 5단계 반복을 **`R×5`로 안내**해 돌 5개, 6단계에서 몇 개 더 → 합계 10개 내외. U1의 10골드와 맞물리며 반복 횟수로 확보량을 맞춘다. **7단계 진입 시 돌이 10개 미만이면 5단계로 되돌리지 말고, 판매 수량을 보유량에 맞춰 안내**한다(예: 돌 7개면 `전량` 버튼을 가리킨다) — 진행이 막히는 상황을 만들지 않는다 |
