# F7-D. 외형 · 도감 · 무료 가챠 기능 명세

> D4/D7의 외형 피스, 도감 보너스, 제작과 무료 크리스탈 가챠를 구현 단위로 분리한다. MVP에는 실제 결제나 유료 크리스탈 구매를 포함하지 않는다.
> **2026-08-20 착수 확정 (C221)**: U1~U6은 제안값 그대로 확정됐다. U7은 30종을 실착 검증한 뒤 한 묶음으로 승인한다. 외형 화면은 일꾼 1~5 탭을 자체 제공하고 `선택 → 장착 버튼` 흐름을 쓴다.

## 1. 데이터와 책임

| 구성 요소 | 책임 |
|---|---|
| `AppearanceCatalog` | 피스 논리 ID, 부위, 희귀도, 획득 가능한 풀 정의 |
| `AppearanceService` | 획득·중복 전환·장착·도감 점수·천장 판정 |
| `AccountProfileService` | 보유 피스, 장착, 점수, 천장 카운터의 영구 저장 |
| 클라이언트 화면 | 보유/미보유, 확률, 비용, 예상 결과를 표시하고 요청 전송 |

피스는 헤어/얼굴/의상 세 부위이며, 보유 피스는 계정 공용이다. 장착 값은 일꾼별로 보관한다. 기본 외형으로의 복귀는 항상 무료다.

## 2. 카탈로그와 도감

각 부위는 일반 3, 고급 3, 희귀 2, 영웅 1, 전설 1로 총 10개를 제공한다. 희귀도 점수는 일반부터 전설까지 1/2/3/4/5점이다.

- 처음 얻은 피스만 도감 점수를 더한다.
- 중복 피스는 희귀도에 비례한 골드로 전환한다.
- 일정 도감 점수마다 모든 일꾼 수레에 +1칸을 준다. 기본 수레 강화 최대 50칸과 별도 합산한다.
- 외형 희귀도 자체가 일꾼별 성능을 직접 바꾸지 않는다.

## 3. 제작과 무료 가챠

| 항목 | 규칙 |
|---|---|
| 제작 | 지정한 광물 조합을 소비해 랜덤 피스 1개; 중복은 골드 전환 |
| 가챠 부위 | 플레이어가 헤어/얼굴/의상 중 선택 |
| 확률 | 일반 50%, 고급 30%, 희귀 15%, 영웅 4%, 전설 1% |
| 천장 | 세 부위가 공유하는 계정 공용 50회 카운터 |
| 50번째 | 플레이어가 원하는 부위를 정해 해당 부위 전설 피스 지급 |
| 크리스탈 | 무료 획득만 제공 — 튜토리얼 보상(1회) + **골드→크리스탈 교환소** (C210, 2026-08-07 신설. 화면에 "테스트 상점"임을 명시). 과제는 C151로 MVP 제외라 **반복 획득은 교환소가 유일한 경로**다. 교환비는 T-06 설계 시 제안→오너 승인 |

가챠/제작 결과, 중복 골드 전환, 천장 증가는 서버가 하나의 거래로 확정하고 F7-A를 통해 즉시 저장한다. 저장 실패 시 결과·비용·카운터를 모두 이전 상태로 되돌린다.

## 4. UI와 연출

- 외형 화면은 부위별 보유 피스, 희귀도, 제작 재료, 가챠 확률, 공유 천장, 도감 보너스를 표시한다.
- 최초 획득·전설·장착 변경만 중요 연출로 강조한다. 반복 동작은 D5/F5의 과밀 제한을 따른다.
- 실제 현금 결제 UI, 유료 가격, 결제 유도 문구는 MVP에 표시하지 않는다.

## 6. 데이터 계약 (상세)

### 6.1 카탈로그 — 코드 상수 테이블

피스 30개(부위 3 × 10)는 고정 목록이라 **`AppearanceService` 내 상수 테이블**로 시작한다. UserDataSet 이관은 콘텐츠가 늘어날 때의 로드맵 항목이다(`Docs` 아님 — 이 프로젝트는 자체 로드맵 없음, docs/00 관리).

```
piece = {
  id = "hair_c1",          -- 논리 ID: {part}_{rarity약자}{n} (hair/face/outfit × c/u/r/e/l)
  part = "hair",           -- hair | face | outfit
  rarity = "common",       -- common(1점) | uncommon(2) | rare(3) | epic(4) | legendary(5)
  itemRuid = "",           -- 아바타 아이템 RUID (§9 승인 후 기입. 빈 값이면 장착 시 외형 무변화 + 로그)
}
```

- 부위 ↔ 아바타 슬롯 매핑: **hair → `CustomHairEquip` · face → `CustomFaceEquip` · outfit → `CustomCoatEquip`(+ 필요시 `CustomPantsEquip` 세트)**. 일꾼 아바타는 이미 `CostumeManagerComponent` + `UseCustomEquipOnly=true` 다(T-04 Phase 4). 기본 외형 = T-04 확정 4슬롯이며, 피스 장착은 해당 슬롯만 덮어쓴다. 기본 복귀는 그 슬롯을 T-04 값으로 되돌리는 것 — 항상 무료(§1).
- ⚠️ `head` 는 대입 슬롯이 없다(As-built 2026-08-04). 헤어 피스는 `CustomHairEquip` 이다.

### 6.2 프로필 원장 — v8 유지, 무버전 확장

`pendingOreCount`·`settings.tuned` 와 같은 방식(누락 시 기본값)으로 v9 없이 확장한다. `NormalizeAppearance` 가 정규화를 소유한다.

```
profile.appearance = {
  owned = { __format = 1, ["hair_c1"] = true, ... }, -- __format: 빈 테이블 JSONEncode 방지 예약 키
  equipped = {                                 -- 일꾼별 장착 (workerIndex 1~5 키)
    ["1"] = { hair = "", face = "", outfit = "" },   -- 빈 문자열 = 기본 외형
  },
  collectionScore = 0,                         -- 도감 점수 (최대 72 = 부위당 24 × 3)
  pityCounter = 0,                             -- 공유 천장 카운터 0~49 (50번째 지급 시 0 리셋)
  pendingPity = false,                         -- 50번째 비용 지불 후 보장 부위 선택 대기
}
```

- 기존 `workerAppearanceJson`("{}")은 **소비자가 없는 호환 필드다 — 쓰지 않고 유지한다**. `appearance`가 단일 원장이다.
- `crystal` 은 v8 에 이미 있다(T-02). 교환소·가챠가 이 필드를 쓴다.

### 6.3 확정 수치 (C221)

| 항목 | 확정값 | 근거 |
|---|---|---|
| 가챠 1회 비용 | **크리스탈 25** | 튜토리얼 보상 25 로 정확히 1회 체험 — 첫 접점을 무료로 보장 |
| 교환비 (C210) | **골드 10 → 크리스탈 1**, 버튼 ×1/×10 | 화면에 "테스트 상점" 명시 |
| 중복 골드 전환 | **일반 5 · 고급 15 · 희귀 40 · 영웅 100 · 전설 250 골드** | 가챠 기대 환급이 비용의 절반을 넘지 않게 |
| 제작 1회 재료 | **돌 60 + 철 20 + 금광석 5**, 부위 선택식 | 확률표는 가챠와 동일 |
| 도감 임계 | **12점마다 수레 +1** — 최대 +6 | 만점 72점 |

### 6.4 도감 수레 보너스의 합산 위치

`GetWorkerCartCapacity` = 기본 20 + 수레 강화(≤50 상한) + 희귀 돌 컬렉션 보너스 + **도감 보너스(신규 — 별도 합산, §2)**. 상한 50 은 **수레 강화 축에만** 적용된다(계약 원문 "별도 합산"). 변경 시 `ApplyCartCapacity` 경로로 즉시 반영 + `RefreshUI` 감지 키 갱신(D-11 계열 주의).

## 7. 서버 계약 (상세)

### 7.1 실행 주체

`AppearanceService` 는 서버 `@Logic` (Economy/Progression 패턴). 프로필 읽기·쓰기는 대상 플레이어의 `AccountProfileService` 를 경유하고, **저장은 요청당 1회의 `SaveProfileAndWait` 트랜잭션**이다. 실패 시 스냅숏 롤백(§3) — `UpdateRareAutoSell` 의 snapshot/restore 패턴을 그대로 쓴다.

### 7.2 RPC 목록 (클라 → `AccountProfileService` Server 경유 → `AppearanceService`)

| RPC | 인자 | 판정 |
|---|---|---|
| `RequestGachaPull` | `part` | 크리스탈 차감 → 롤(§3 확률) → 천장 +1 → 신규면 owned+점수 / 중복이면 골드 전환 → 저장. **50번째는 롤 대신 `pendingPityPart` 상태로 전환**(§7.4) |
| `RequestPityClaim` | `part` | 천장 도달 상태에서만. 해당 부위 전설 지급(이미 보유면 중복 전환) → 카운터 0 |
| `RequestCraft` | `part` | 광물 차감 → 롤 → 이후 가챠와 동일 (천장 카운터 **증가 없음** — 천장은 가챠 전용, §11 U5) |
| `RequestEquipPiece` | `workerIndex, part, pieceId("" = 기본)` | 보유·일꾼 보유 검증 → equipped 갱신 → 아바타 반영 |
| `RequestCrystalExchange` | `count` | 골드 차감 → 크리스탈 지급 (클램프·상한 없음, 거절은 골드 부족뿐) |

거절 사유는 **docs/23 §6.3 의 코드 6종이 전 목록**이다. 문구는 `DescribeShortfall`(부족분 숫자) 체계를 재사용하고, `LastTransactionMessage` 로 내린다. 모달 스냅숏 방식(T-03 표준 패턴)으로 그린다.

### 7.3 @Sync 표기 계약 — JSON 한 장 + 스칼라 최소 (T-02 교훈)

| @Sync | 내용 |
|---|---|
| `AppearanceInfoJson` | 카탈로그 전체 × 보유 여부 · 일꾼별 장착 · 도감 점수/다음 임계 · 천장 카운터/50 · 비용·교환비 표기값. **클라이언트는 파싱만, 재계산 0줄** (F7-B §5.6.3 준용) |
| `AppearanceCollectionScore` (integer) | HUD·요약용 스칼라 |
| `AppearancePityCounter` (integer) | 뽑기 버튼 옆 "N/50" 표기용 |

`RefreshUI` 변경 감지 키에 세 값 모두 넣는다 — 빠지면 무증상 미갱신(D-11).

### 7.4 천장(50번째)의 상태 기계

49→50번째 뽑기는 **롤이 아니라 "부위 선택 대기"** 다: `pityCounter == 49` 에서 `RequestGachaPull` 이 오면 비용만 차감하고 `pendingPity = true` 저장, 클라이언트에 부위 선택 UI 를 요구한다. `RequestPityClaim(part)` 이 지급·리셋한다. 저장 실패 시 §3 대로 전부 롤백. **`pendingPity` 상태로 재접속해도 선택 UI 가 다시 뜬다** — 비용을 낸 상태를 잃지 않는다.

| 전설 획득 | 카드 + 토스트 + 강조(펄스 1회) — **중요 이벤트 채널은 쓰지 않는다**(광산 이벤트 전용) |
| 중복 획득 | 카드에 "골드 +N 전환" 문구만 — 추가 연출 없음 |
| 장착 변경 | 일꾼 아바타 즉시 반영 + 토스트 없음 (화면에서 이미 보인다) |

### 8.6 클라이언트 금지 사항

확률·비용·부족분·임계 재계산 금지 — `AppearanceInfoJson` 파싱만 (T-03 과 동일 원칙). 검증은 서버 단일 소유.

## 9. 자산 계약 — 피스 30종 아바타 아이템

- `msw-search` `searchAvatarItems` 로 부위별 후보 수집 → **`msw-asset-verify` 착용 확인**(썸네일이 아니라 실착용이 최종 판정) → **docs/21 에 §8 "외형 피스 승인표" 신설** 후 오너 승인. 승인 전 카탈로그 `itemRuid` 는 빈 값(장착해도 외형 무변화 + 로그 1회 — F5 §4 무음 원칙 준용).
