# D4. 일꾼 캐릭터 기획서 (⑤단계 전반)

> 2026-07-19 작성. [02-마스터-GDD.md](02-마스터-GDD.md)의 1인 세션·PC 우선 원칙과 [04-자원-인벤토리.md](04-자원-인벤토리.md)의 공용 창고/일꾼별 수레 경계를 따른다.

> **구현 상태 (2026-07-19): D4-A 완료, D4-B 미착수.** Maker에서 §7 W1~W8을 검증했다. 현재 외형은 기존 유효 스프라이트와 Worker02 색상 틴트를 사용하며, 랜덤 아바타 조합은 다음 작업이다.

## 1. 목표와 범위

D4의 목표는 한 플레이어가 일꾼 2명에게 서로 다른 프로그램을 배정하고, 두 일꾼이 같은 광산 틱에서 독립적으로 작업하게 만드는 것이다.

- D4-A: 다중 일꾼 모델·배치, 선택 UI, 프로그램 대상 전환, 일꾼별 손·수레·실행 상태, 공용 창고
- D4-B: 랜덤 외형 조합 풀, 신규 일꾼 획득 연출, 외형 저장
- 제외: 멀티플레이어 권한 분리, 일꾼 간 거래, 셀 예약/길찾기, 영구 저장

## 2. 확정 기본 규칙

| 항목 | D4 기본값 | 이유 |
|---|---|---|
| 세션 소유자 | 1인 | 기존 MVP 범위 유지 |
| 시작 일꾼 수 | 2명 | 다중 배정 UX를 최소 비용으로 검증 |
| 틱 처리 | 등록된 각 일꾼이 틱당 최대 액션 1개 | 기존 인터프리터의 예측 가능성 유지 |
| 같은 셀 겹침 | 허용 | 충돌 예약·교착 상태를 D4 범위에서 제외 |
| 창고 | 세션 공용 | 누적 성장 지표를 하나로 유지 |
| 손·수레·프로그램 | 일꾼 인스턴스별 | 한 일꾼의 실패나 만재가 다른 일꾼을 막지 않음 |
| 선택 UI | PC 편집기 상단의 `일꾼 1`, `일꾼 2` 버튼 | 현재 프로그램 전송 대상과 HUD 대상을 한 번에 전환 |

## 3. 런타임 소유권

| 상태 | 소유 컴포넌트 | 공유 여부 |
|---|---|---|
| 광맥 stage·회복 | 맵의 `VeinTickSimulator` | 공유 |
| 창고 `DepotStone` | 맵의 `VeinTickSimulator` | 공유 |
| 현재 셀·시작 셀 | 각 `WorkerController` | 개별 |
| 손 `PendingOre` | 각 `WorkerController` | 개별 |
| 수레 `CartCount/CartCapacity` | 각 `WorkerController` | 개별 |
| 프로그램 스택·실행 상태 | 각 `WorkerController` | 개별 |
| 현재 UI 선택 | `BlockProgramController` | 클라이언트 단일 선택 |

`VeinTickSimulator.AdvanceWorkers()`는 등록 순서대로 모든 일꾼을 한 번씩 호출한다. 한 일꾼의 제어 블록 평가나 액션 실패가 다음 일꾼의 틱을 소비하지 않는다.

## 4. 모델과 맵 배치

- 공용 모델: `RootDesk/MyDesk/Models/Farm/Worker.model`, modelId `worker`
- 필수 컴포넌트: `TransformComponent`, `SpriteRendererComponent`, `MovementComponent`, `KinematicbodyComponent`, `script.WorkerController`
- 맵 모드: RectTile(`TileMapMode=1`), 동적 Body는 `KinematicbodyComponent`
- Worker01: `WorkerIndex=1`, 시작 셀 `(0,0)`
- Worker02: `WorkerIndex=2`, 시작 셀 `(0,1)`
- 시작 셀은 모델 인스턴스의 `StartCellX/Y`로 지정하고, `OnBeginPlay`에서 RectTile 셀을 월드 좌표로 변환한다.

기존 `Drone.model`은 이전 커밋과 맵 이력 호환을 위한 레거시 원본으로 남겨 두되 신규 배치는 사용하지 않는다.

## 5. PC 선택·배정 UX

1. 블록 편집기 상단에서 일꾼을 선택한다.
2. 선택된 버튼에는 `✓`를 표시한다.
3. Run/Stop은 선택된 일꾼에게만 전달한다.
4. 다른 일꾼으로 전환해도 먼저 실행한 프로그램은 계속된다.
5. Run 라벨은 선택된 일꾼의 `ProgramState`만 반영한다.
6. HUD의 손·수레는 선택된 일꾼을, 창고 수량은 공용 원장을 표시한다.

편집 중인 블록 목록은 D4-A에서 공용 작업대처럼 유지한다. 전송 이후 프로그램과 실행 스택은 각 일꾼이 독립 소유한다. 일꾼별 편집 초안 저장은 D4-B 이후 개선 항목이다.

## 6. 외형 단계

### D4-A 임시 구분

기존 유효 SpriteRUID를 유지하고 Worker02에 색상 틴트를 적용해 두 일꾼을 즉시 구분한다. 빈 SpriteRUID는 허용하지 않는다.

### D4-B 랜덤 외형

- MSW 아바타 파이프라인으로 전환하고 몸/헤어/얼굴/상의/하의/신발의 허용 조합 풀을 정의한다.
- 무작위 선택은 서버가 결정하고 결과 슬롯 ID만 저장·동기화한다.
- 금지 조합과 누락 슬롯에는 기본 세트를 적용한다.
- 랜덤 외형이 완료되기 전에는 D4 전체를 완료로 표기하지 않는다.
