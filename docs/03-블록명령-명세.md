# D2. 블록 명령 체계 명세서 (③단계 — 런타임 인터프리터)

> 2026-07-12 작성. 용어는 [01-테마전환-용어집.md](01-테마전환-용어집.md), 전체 구조는 [02-마스터-GDD.md](02-마스터-GDD.md) 기준.
> **확정 결정**: 반복·조건은 **서버 런타임 인터프리터**로 실행한다(조립 시 전개 방식 아님). 자연어 입력은 **전용 텍스트창**으로 받는다(게임 채팅 후킹 미채택).

## 1. 범위

- 포함: 블록 카탈로그, 프로그램 데이터 구조, 인터프리터 실행 모델, 안전 규칙, 블록 조립 UI 확장, 전용 텍스트창, 자연어 확장 규칙, 수용 기준
- 제외: 수레 용량·창고 저장 수치(D3), 다중 일꾼 배정(D4). 단, `load`/`unload` 블록과 수레 조건은 **인터페이스만** 이 문서에서 예약한다 — D3 없이도 스텁(로그만)으로 구현 가능해야 한다.

## 2. 블록 카탈로그

### 액션 블록 — 실행 시 1틱 소비

| 블록 | 파라미터 | UI 라벨 | 동작 | 실패 시(틱은 소비) |
|---|---|:--:|---|---|
| 이동 | dir: E/W/N/S | E/W/N/S | 해당 방향 1셀 이동 | 맵 경계 밖이면 제자리 + `[Worker] blocked` 로그 |
| 채굴 | — | M | 현재 셀 광맥의 ReserveStage ≥ 1이면 1단계 채굴(광물 1 획득 예약, ReserveStage −1… D3 확정 전에는 로그만) | 광맥 없음/고갈이면 아무 일 없음 + 로그 |
| 싣기 | — | L | (D3 연동) 들고 있는 광물을 수레에 적재. **③단계에서는 로그만 출력하는 스텁** | — |
| 내리기 | — | U | (D3 연동) 창고 셀에서 수레 비우기. **③단계에서는 로그만 출력하는 스텁** | — |

> **구현 전제 (프로그래머 확인 필요)** — 현재 `DroneController`에는 경계 검사가 없어 격자 밖으로도 텔레포트한다. S10(경계 막힘)을 위해 이동 전 목표 셀 유효성을 검사할 것: `RectTileMapComponent:GetTile(targetCell)`의 반환 `RectTileInfo.Name`이 빈 문자열이면(=타일 없음) 격자 밖으로 간주해 이동 취소 + `[Worker] blocked`. (검증 완료 API: `GetTile(Vector2Int)`, `ToWorldPosition`, `TileCount` 존재 확인함.) 또한 채굴·창고 시나리오를 실행하려면 **맵에 광맥 셀 여러 개와 창고 셀 1개가 배치돼 있어야 한다** — 현재 `farm01.map`은 (3,3) 한 셀만 시드하므로 맵 오서링이 선행되어야 함.

### 제어 블록 — 평가 시 틱 소비 없음 (§4 평가 한도 적용)

| 블록 | 파라미터 | UI 라벨 | 동작 |
|---|---|:--:|---|
| 반복 | count: 2/3/5/10/∞ | R×n / R∞ | body를 count회 반복. **∞는 프로그램 최상위 깊이에서만 허용, 1개까지** |
| 조건 | cond (아래 표) | IF | 평가 시점의 월드 상태로 판정, 참이면 body 실행. else 분기는 v1 제외 |
| 끝 | — | ] | 직전에 열린 반복/조건 블록을 닫음 (UI 전용 — 직렬화 시 중첩 구조로 흡수) |

### 조건(cond) 종류

| cond 키 | 의미 | 판정 기준 | 단계 |
|---|---|---|:--:|
| `ore_present` | 현재 셀에 광물 있음 | 현재 셀 ReserveStage ≥ 1 | ③ |
| `ore_absent` | 현재 셀에 광물 없음 | ReserveStage == 0 또는 광맥 아님 | ③ |
| `cart_full` / `cart_empty` | 수레 가득/비어 있음 | D3 인벤토리 연동 후 활성 (③에서는 항상 false/true 스텁) | ④ |

## 3. 프로그램 데이터 구조 (클라 → 서버 직렬화 형식)

`RunProgram(table program)`으로 전달하는 중첩 테이블. 배열 순서 = 실행 순서.

```lua
-- 예: "반복 3회 [ 동으로 이동, IF 광물 있으면 채굴 ]" 후 "남으로 이동"
{
  { type = "repeat", count = 3, body = {
      { type = "move", dir = "E" },
      { type = "if", cond = "ore_present", body = {
          { type = "mine" },
      }},
  }},
  { type = "move", dir = "S" },
}
```

- `type`: `"move" | "mine" | "load" | "unload" | "repeat" | "if"` (기존 `action` 키에서 개명 — 기존 `harvest`/`plant`는 폐기)
- `repeat.count`: integer 2~99 또는 문자열 `"inf"`
- **서버 재검증(필수)**: 총 블록 수(중첩 포함) ≤ 30, 중첩 깊이 ≤ 3, `"inf"`는 최상위 1개만, 알 수 없는 `type`/`cond`/`dir`는 프로그램 전체 거부 + `[Worker] program rejected: <사유>` 로그. 클라 검증은 UX용일 뿐 신뢰하지 않는다.

## 4. 인터프리터 실행 모델

- **상태**: `Idle`(프로그램 없음/종료) ↔ `Running`. `RunProgram` 수신 시 기존 실행을 즉시 중단하고 새 프로그램으로 재시작. `StopProgram()` RPC(신규) 수신 시 `Idle`로.
- **실행 구조**: 스택 프레임 방식. 프레임 = `{ list, index, remaining }` (remaining은 반복 잔여 횟수, `"inf"`는 감소 없음).
  - 매 틱: 현재(스택 최상단) 프레임의 `list[index]`를 본다 →
    - 액션 블록이면 실행하고 `index+1`, **이 틱 종료**
    - `repeat`면 **먼저 부모 프레임 `index+1`**(자식 종료 후 이 반복 블록 다음부터 재개하기 위함) → 그 다음 자식 프레임 push(`list=body, index=1, remaining=count`)
    - `if`면 cond 즉시 평가 → **참이면 부모 프레임 `index+1` 후** 자식 프레임 push(`list=body, index=1, remaining=1`) / 거짓이면 부모 `index+1`만
    - 리스트 끝(`index > #list`)이면: 반복 프레임은 `remaining` 감소 후 남아 있으면(또는 `"inf"`) `index=1`로 되감기(pop 안 함), 소진됐거나 반복 프레임이 아니면 pop
    - 루트 프레임까지 pop되어 스택이 비면 `Idle` 전환 + `[Worker] program finished` 로그
  - ⚠️ **부모 index 선(先)증가가 없으면** 자식이 끝난 뒤 같은 `repeat`/`if` 블록으로 무한 재진입한다. push 전에 부모 index를 반드시 진행시킬 것.
- **평가 한도(무한 zero-cost 루프 방지)**: 한 틱 안에서 제어 블록 평가·프레임 전환은 최대 **20회**. 한도에 도달하면 그 틱은 강제 대기(액션 없이 종료)하고 `[Worker] eval limit hit` 로그. → 빈 body 무한 반복 같은 프로그램도 서버가 멈추지 않음을 보장.
- **틱 소비 요약**: 액션 = 1틱. 제어 블록 평가 = 0틱(한도 내). 실패한 액션(경계 밖 이동 등)도 1틱 소비 — "잘못 짠 프로그램은 느리다"는 알고리즘적 피드백을 위해 의도된 규칙.

## 5. 안전 규칙 총괄표

| 항목 | 한도 | 위반 시 |
|---|:--:|---|
| 총 블록 수(중첩 포함) | 30 | 서버가 프로그램 거부 |
| 중첩 깊이 | 3 | 서버가 프로그램 거부 |

| 실행 중 재실행 | 허용 | 기존 중단 후 새 프로그램 시작 |

## 6. 자연어 → 블록 확장 규칙 (기존 `ParseChatCommand` 확장)

기존 유지: 방향어(오른/왼/위/아래·동/서/남/북), 수사(숫자·한/두/세/네/다섯) → 이동 반복. 행동어는 D0 §4대로 교체(수확→캐/채굴, 심기 삭제, 실어/내려 신설).

신규 패턴 (토큰 부분 일치, 어순 무관 순차 처리):

| 입력 패턴 | 변환 | 예 |
|---|---|---|
| "…N번 반복" (직전 문장 구간을 body로) | `repeat(N)[...]` | "동쪽으로 가서 캐기를 3번 반복" → R×3[E, M] |
| "계속", "끝까지" | `repeat(inf)[...]` | "캐고 서쪽 가기를 계속" → R∞[M, W] |
| "광물(이) 있으면 …" | `if(ore_present)[...]` | "광물 있으면 캐" → IF[M] |
| "광물(이) 없으면 …" | `if(ore_absent)[...]` | "없으면 동쪽으로 가" → IF(absent)[E] |
| "가득 차면 …" | `if(cart_full)[...]` | (④단계 활성) |

- v1 단순화 원칙: 반복/조건의 **body 경계는 "~기를", "~면" 조사 앞까지의 구간**으로 한정하고, 한 문장에 반복·조건 각 1개까지만 인식. 그 이상은 "문장을 나눠 입력해 주세요" 피드백.
- 인식 실패 토큰은 무시하되 피드백 라인에 표시(§8). 전체가 무인식이면 변환 실패 처리.

## 7. 블록 조립 UI 확장 (`BlockProgramUI.ui` + `BlockProgramController`)

- **팔레트 버튼 추가**: 기존 E/S/M(구 H)에 더해 W, N, L, U, `반복`, `IF광물`, `끝(])` — 총 10종. P(심기) 버튼 제거.
- **괄호 방식 조립**: `반복`/`IF광물` 버튼 → 여는 블록 추가, `끝` 버튼 → 가장 최근에 열린 제어 블록을 닫음. 닫히지 않은 블록이 있는 채로 Run을 누르면 자동으로 모두 닫고 실행(토스트 안내).
- **반복 횟수 입력**: 프로그램 리스트에서 반복 블록을 탭하면 count가 2→3→5→10→∞ 순환. (전용 숫자 입력 UI는 v2)
- **프로그램 리스트 표시**: 중첩 깊이만큼 들여쓰기. 예: `R×3 [ E, IF [ M ] ], S`. 현재 `programText` 단일 TextComponent를 유지하되 줄바꿈+들여쓰기 문자열로 렌더 (전용 리스트 위젯은 v2).
- **버튼 추가**: `정지`(StopProgram RPC). 기존 Run/Clear 유지.
- **실행 중 표시**: Running 상태 동안 Run 버튼 라벨을 "재실행"으로. (상태 통지는 서버→클라 이벤트, 구현 방식은 프로그래머 재량)
- `.ui` 수정은 UIBuilder 경유(플랫폼 규칙), 신규 버튼의 UUID는 `BlockProgramController` property 바인딩에 추가.

## 8. 전용 자연어 텍스트창 명세

- **구성**: TextInput(1줄) + `변환` 버튼 + 피드백 TextComponent(1줄). 블록 조립 패널 하단에 배치.
- **동작**: `변환` 클릭 → `ParseChatCommand(text)` 호출 → 변환된 블록이 **프로그램 리스트에 채워질 뿐 자동 실행하지 않는다** (현재 코드의 `OnRunClicked()` 자동 호출 제거). 유저가 결과를 눈으로 확인하고 Run을 눌러 실행 — "시스템이 블록을 대신 조립해준다"는 기획 의도의 핵심 UX.
- **피드백 라인**:
  - 성공: `"5개 블록으로 변환했어요: E, E, M, R×3[…]"` 
  - 부분 인식: `"'거시기'는 이해하지 못했어요 (나머지 4개 블록 변환됨)"`
  - 전체 실패: `"이해하지 못했어요. 예: 오른쪽으로 두 칸 가서 캐"`
- 게임 채팅 후킹은 **미채택** — 대회 시연 직전 여유 시에만 접두어(`!`) 방식으로 검토(별도 기획 불요, 같은 파서 재사용).

## 9. 수용 기준 (전 시나리오 통과 = ③단계 완료)

각 시나리오는 Maker Play 모드에서 실행하고 `logs`로 검증한다.

| # | 시나리오 | 기대 결과(로그) |
|:-:|---|---|
| S1 | `R×3[E, M], S` 실행 | move E / mine 이 3회 교대로, 마지막 move S, `program finished` — 총 7틱 |
| S2 | 광물 있는 셀에서 `IF광물[M]` | mine 실행 로그 1건 |
| S3 | 고갈 셀에서 `IF광물[M]` | mine 로그 없음, 즉시 `program finished` |
| S4 | `R∞[E, W]` 실행 후 정지 버튼 | E/W 진동 반복, Stop 시 `[Worker] stopped by user` |
| S5 | 빈 body `R∞[]` 실행 | 서버 멈춤 없음, 틱마다 `eval limit hit`, 게임 정상 동작 |
| S6 | 31블록 또는 깊이 4 프로그램 전송 | `program rejected` 로그, 일꾼 무반응 |
| S7 | 텍스트창 "오른쪽으로 두 칸 가서 캐" | 리스트에 `E, E, M` 표시(자동 실행 안 됨) → Run 시 정상 실행 |
| S8 | 텍스트창 "광물 있으면 캐기를 계속" | 리스트에 `R∞[IF[M]]` 표시 |
| S9 | 실행 중 새 프로그램 Run | 기존 즉시 중단, 새 프로그램 1틱째부터 실행 |
| S10 | 경계 셀에서 밖으로 이동 | `blocked` 로그 + 1틱 소비 후 다음 블록 진행 |
