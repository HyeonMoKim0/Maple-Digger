# D6. 광산 맵 · 콘텐츠 배치 기획서

> 2026-07-26 초안. 기준 문서: D1 마스터 GDD, D3 자원·인벤토리, D4 일꾼 캐릭터, D5 비주얼·사운드.  
> 적용 맵: `map/farm01.map` (RectTile, `TileMapMode=1`).

## 1. 목표

현재 `VeinTickSimulator`에 있는 광맥·창고 좌표의 임시 하드코딩을 제거하고, **맵 작성자가 Maker에서 읽고 수정할 수 있는 배치 데이터**를 단일 기준으로 만든다. 게임 규칙은 서버 시뮬레이터가 계속 소유하고, 맵은 “어디에 무엇이 있는가”만 선언한다.

## 2. 고정 결정

| 항목 | 결정 |
|---|---|
| 기준 맵 | MVP는 `farm01` 하나만 사용한다. |
| 좌표 단위 | 모든 배치는 RectTile 셀 좌표 `(x, y)`를 쓴다. 월드 좌표는 런타임에서 `RectTileMapComponent:ToWorldPosition`으로 변환한다. |
| 단일 기준 | 광맥·창고의 ID, 셀, 광물 종류, 초기 stage, 회복 주기는 맵의 `MineLayoutConfig`에만 작성한다. 같은 좌표를 스크립트 상수나 장식 마커에 중복 기입하지 않는다. |
| 런타임 원장 | `VeinTickSimulator`가 시작 시 설정을 복사해 stage·회복·창고 수량을 관리한다. 원본 맵 설정은 실행 중 바꾸지 않는다. |
| 이동 규칙 | 설정된 모든 광맥·창고·일꾼 시작 셀은 실제 RectTile 타일 위에 있어야 한다. 이동 가능 여부는 기존 `WorkerController:IsCellWalkable`이 최종 판정한다. |
| 셀 겹침 | 일꾼끼리 겹침은 D4 결정대로 허용한다. 광맥과 창고는 서로 같은 셀에 둘 수 없다. |

## 3. MVP 레이아웃

현재 검증된 동선을 데이터화한 첫 레이아웃이다. 수치 밸런싱은 D3의 기본값을 따른다.

| ID | 종류 | 셀 좌표 | 광물 | 초기 stage | 회복 주기 | 비고 |
|---|---|---|---|:--:|:--:|---|
| `depot-main` | 창고 | `(0, 0)` | — | — | — | 공용 창고. Worker01 시작 셀과 겹치는 것은 허용 |
| `vein-stone-01` | 광맥 | `(1, 0)` | stone | 3 | 5틱 | 기본 채굴 동선 |
| `vein-stone-02` | 광맥 | `(2, 0)` | stone | 3 | 5틱 | 기본 채굴 동선 |
| `vein-stone-03` | 광맥 | `(2, -1)` | stone | 3 | 5틱 | 꺾이는 동선 검증 |
| `vein-stone-04` | 광맥 | `(3, -1)` | stone | 3 | 5틱 | 가장 먼 MVP 광맥 |
| `worker-01-start` | 시작점 | `(0, 0)` | — | — | — | WorkerIndex 1 |
| `worker-02-start` | 시작점 | `(0, 1)` | — | — | — | WorkerIndex 2 |

이 표는 “활성 콘텐츠 목록”이며, 장식 타일·벽·배경은 여기에 포함하지 않는다. 맵 크기와 모든 이동 가능 타일의 범위는 Maker에서 실제 타일을 기준으로 유지하며, 위 셀이 존재하지 않는 변경은 유효하지 않다.

## 4. 콘텐츠 확장 규칙

### 4.1 광물

| oreType | 상태 | 회복 주기 | 시각 구분 | 배치 원칙 |
|---|---|:--:|---|---|
| `stone` | 활성 | 5틱 | 회색/청회색, 4단계 스프라이트 | 시작 구역의 기본 자원 |
| `iron` | 예약 | 10틱 | 철색 + 아이콘 | stone과 다른 경로에 배치 |
| `gold` | 예약 | 20틱 | 금색 + 별도 형태 | 위험/보상 기획이 확정된 뒤 배치 |

- 한 광맥은 오직 하나의 `oreType`만 가진다.
- 새로운 광물은 D3의 자원·HUD·창고 표시가 해당 ID를 처리한 후에만 맵에 배치한다.
- 동일 셀에 여러 광맥을 겹치거나 stage를 0보다 작게, 최대 stage보다 크게 설정하지 않는다.

### 4.2 동선과 난이도

- MVP는 길찾기를 요구하지 않는다. 플레이어가 블록으로 명시한 방향 이동만 수행한다.
- 확장 맵은 “채굴 구역 → 창고 복귀” 루트를 최소 하나 이상 제공해야 한다.
- 막다른 길, 일방 통행, 위험 타일, 셀 예약은 별도 기획 없이는 추가하지 않는다.
- 맵 변경 시 D2의 경계 차단과 D4의 두 일꾼 동시 실행 시나리오를 다시 검증한다.

## 5. 월드 마커와 데이터의 관계

| 요소 | 맵에서 보유하는 항목 | 런타임에서 보유하는 항목 | D5 연결 |
|---|---|---|---|
| 광맥 | ID, 셀, oreType, 초기 stage, 회복 주기, `VeinMarker` 참조 | 현재 stage, 회복 경과 | Marker가 현재 stage를 보고 스프라이트/효과 선택 |
| 창고 | ID, 셀, `DepotMarker` 참조 | ore별 누적 수량 | 하역 시 마커 강조 |
| 일꾼 시작점 | WorkerIndex, 셀 | 현재 셀, 수레, 프로그램 | 선택 링과 행동 연출 |

- `VeinMarker`와 `DepotMarker`는 보이는 위치를 담당할 뿐, 광물 수량과 stage를 자체 저장하지 않는다.
- 광맥 ID와 마커의 연결이 끊어진 경우 해당 맵은 Play 전에 검증 실패로 처리한다. 임시 좌표 추측이나 첫 번째 마커 자동 선택은 허용하지 않는다.

## 6. 맵 작성 절차

1. RectTileMap에 이동 가능한 바닥 타일을 먼저 확정한다.
2. `MineLayoutConfig`에 창고, 광맥, 일꾼 시작점 데이터를 입력한다.
3. 각 광맥 ID에 한 개의 `VeinMarker`, 창고 ID에 한 개의 `DepotMarker`를 배치·연결한다.
4. D5 승인 자산의 RUID를 마커 모델에 적용한다.
5. 구조 검증 후 Play에서 레이아웃 로드 로그와 경계 이동을 확인한다.

## 7. 범위와 완료 판정

- 포함: `farm01` 데이터화, 광맥/창고/일꾼 시작점 ID 규칙, 마커 연결, 콘텐츠 확장 규칙.
- 제외: 새 맵 선택 화면, 절차 생성, 길찾기, 전투/위험 타일, 멀티플레이어 소유권.

| # | 시나리오 | 완료 조건 |
|---|---|---|
| M1 | `farm01` 시작 | 4개 광맥·창고 1개·일꾼 시작점 2개가 설정 ID로 로드됨 |
| M2 | 설정 셀 하나를 타일 밖으로 변경 | Play 전 검증에서 ID와 좌표를 포함한 오류가 보고됨 |
| M3 | 광맥 ID를 마커와 연결 | 광맥 stage 변화가 해당 마커 하나에만 반영됨 |
| M4 | 광맥 한 개의 회복 주기 변경 | 해당 광맥만 변경된 주기로 회복함 |
| M5 | 두 일꾼이 서로 다른 루트 실행 | 기존 D4-A처럼 독립 실행·공용 창고가 유지됨 |
