# D6. 광산 맵 · 콘텐츠 배치 기획서 (MVP 통합)

> 최신 결정 기준은 [10-MVP-성장-경제-통합명세.md](10-MVP-성장-경제-통합명세.md) (D7)다. 이 문서는 맵 작성자가 편집할 정적 배치와 월드 콘텐츠의 계약을 정의한다.

## 1. 목표와 원칙

MVP는 세 개의 광산을 제공한다. 광맥·창고·일꾼 시작점은 맵 설정이 단일 기준이고, 서버 시뮬레이터는 이를 복사해 세션 중의 stage·회복·특별 광맥을 관리한다.

- 모든 배치는 RectTile 셀 좌표 `(x, y)`로 작성하고, 월드 좌표 변환은 런타임에서만 한다.
- 각 광산에는 Depot가 정확히 하나 있다. Depot와 일꾼 시작점의 셀 겹침은 허용한다.
- 일반 광맥과 Depot는 같은 셀에 둘 수 없고, 광맥끼리도 겹칠 수 없다.
- 광맥의 현재 stage와 특별 광맥은 세션 상태다. 해금·광산 강화·계정 창고는 계정 상태다.
- 길찾기는 없다. 넓어지는 레이아웃을 플레이어의 블록 루트 설계 과제로 만든다.

## 2. 광산 목록과 난이도

| MineId | 이름 | 크기 초안 | 일반 광물 | 자동화 과제 | 대표 강화 효과 |
|---|---|---:|---|---|---|
| `beginner_mine` | 초보 광산 | 8×6 | 돌 | 단순 왕복 | 광물 획득량 |
| `deep_mine` | 깊은 광산 | 14×8 | 돌, 철 | 먼 철 광맥까지 운반 | 광맥 회복 속도 |
| `gem_mine` | 보석 광산 | 20×12 | 돌, 철, 금 | 여러 구역을 잇는 효율 루트 | 희귀 광물 확률 |

세 맵은 순서대로 해금하며, 이전 광산의 일반 광물도 후속 맵에 함께 배치한다. 입장에 소모되는 비용은 없다. 맵 해금·강화 비용은 D3/D7 경제 규칙을 따른다.

## 3. 레이아웃 초안

| 광산 | Depot/시작 | 근거리 구역 | 중거리 구역 | 원거리 구역 |
|---|---|---|---|---|
| 초보 광산 | Depot `(0,0)` | 돌 4개를 x=1~3 부근에 배치 | — | — |
| 깊은 광산 | Depot `(0,0)` | 돌 2~3개 | 철 3~4개를 x=6~10 부근에 배치 | — |
| 보석 광산 | Depot `(0,0)` | 돌 구역 | 철 중간 구역 | 금을 멀리 분산 배치 |

이 표는 동선 의도이며 최종 셀 목록은 각 맵의 `MineLayoutConfig`에 작성한다. 맵 크기와 이동 가능 타일을 먼저 확정하고 그 안의 셀만 설정한다.

## 4. 정적 콘텐츠 데이터

각 맵은 다음을 `MineLayoutConfig`에 보유한다.

| 데이터 | 필수 항목 |
|---|---|
| 맵 메타 | `mineId`, 표시 이름, 대표 광물, 광산 강화 효과, `MapLevel` 1~10 참조 |
| Depot | 논리 ID, 셀, marker ID |
| 일반 광맥 | 논리 ID, 셀, `oreType`, 초기 stage, 회복 주기, marker ID |
| 일꾼 시작점 | WorkerIndex, 셀 (1~5를 지원) |
| 특별 광맥 후보 | 출현 가능한 셀/구역 ID와 marker 생성 규칙 |

일반 광맥의 광물은 `stone`, `iron`, `gold` 중 하나다. 회복 주기·초기 stage는 맵별 밸런싱 값이고, 광산 강화로 수정될 수 있는 기본값이다.

## 5. 특별 광맥과 희귀 광물

- 특별 광맥은 일반 광맥과 별도로 일정 시간마다 무작위 출현한다. 기본 목표는 약 5분, 광산 강화·진행도로 단축 가능하다.
- 한 번에 1~2개, 세션 전체에서 동시 최대 3개만 활성화한다. 활성 특별 광맥은 그 플레이 세션 동안 유지한다.
- 특별 광맥은 전용 스프라이트·반짝임·효과음으로 일반 광맥과 구분한다. 지도 위치 표시와 HUD 아이콘, 토스트를 함께 제공한다.
- 일반/특별 광맥 채굴 시 희귀 광물 드롭 확률은 각각 기본 1%/5%다. 희귀 광물의 계정 효과·입고 처리는 D3이 소유한다.

## 6. 마커와 런타임의 경계

| 요소 | 맵 설정/마커가 보유 | 서버 런타임이 보유 | 시각 연결 |
|---|---|---|---|
| 일반 광맥 | ID, 셀, oreType, 초기값, marker 연결 | 현재 stage·회복 경과 | stage와 oreType으로 스프라이트 변경 |
| 특별 광맥 | 후보 셀/연출 규칙 | 출현 여부·남은 세션 상태 | 생성/소멸 이벤트와 전용 marker |
| Depot | ID, 셀, marker 연결 | 입고 요청 처리 | 하역 순간 강조 |
| 일꾼 시작점 | WorkerIndex, 셀 | 현재 셀·수레·프로그램 | 선택 링·행동 연출 |

마커는 수량과 stage를 보관하지 않는다. ID-마커 연결이 없거나 중복되면 Play 전 검증에서 실패해야 하며, 첫 번째 마커를 임의 선택하는 보정은 허용하지 않는다.

## 7. 맵 작성 절차

1. RectTileMap의 맵 크기와 이동 가능한 바닥을 확정한다.
2. `MineLayoutConfig`에 Depot·일반 광맥·시작점·특별 광맥 후보를 입력한다.
3. 일반 광맥/Depot marker를 논리 ID로 1:1 연결하고, 특별 광맥용 전용 marker 또는 생성 모델을 연결한다.
4. D5 승인 RUID를 적용한다.
5. 구조 검증 후 각 맵에서 시작·이동 경계·하역·특별 광맥 출현을 확인한다.

## 8. MVP 수용 기준

| # | 시나리오 | 완료 조건 |
|---|---|---|
| M1 | 세 광산을 차례로 해금·입장 | 각 맵의 대표 광물과 레이아웃이 로드되고 입장 비용 없음 |
| M2 | 깊은/보석 광산에서 채굴 | 돌·철·금 배치가 표와 일치하고 이전 광물도 유지 |
| M3 | WorkerIndex 1~5 시작 | 유효한 시작 셀에서 등록, Depot와의 시작 셀 겹침 허용 |
| M4 | 잘못된 셀·중복 marker·중복 광맥 | ID와 좌표를 포함한 Play 전 검증 오류 |
| M5 | 특별 광맥 출현 | 1~2개 출현, 동시 최대 3개, 지도/HUD/월드 연출 일치 |
| M6 | 맵 전환 | 모든 일꾼 정지, 세션 광맥 초기화, 새 맵 수동 실행 |
