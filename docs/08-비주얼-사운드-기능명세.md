# F5. 비주얼 · 사운드 기능 명세

> D5 구현 계약. 서버가 게임 결과를 확정하고, 클라이언트는 읽기 전용 동기화 상태와 중요한 이벤트를 시각화·재생한다.

## 1. 책임 분리

| 모듈 | 실행 위치 | 책임 | 금지 |
|---|---|---|---|
| `VeinTickSimulator` | ServerOnly, 맵 | 일반/특별 광맥 stage·회복·드롭 결과 | RUID 선택·효과음 |
| `WorkerController` | ServerOnly, 일꾼 | 이동·채굴·적재·하역 결과, 행동 이벤트 발행 | 클라이언트 효과 직접 생성 |
| `VeinMarkerController` | ClientOnly, 일반 marker | oreType·stage에 따른 렌더링 | stage 변경·회복 계산 |
| `SpecialVeinMarkerController` | ClientOnly, 특별 marker | 스폰/위치/강조 연출 | 스폰 확률·최대 수 판정 |
| `WorkerVisualController` | ClientOnly, 일꾼 | 선택 링·행동 효과·아바타 표시 | 프로그램·수레·창고 변경 |
| `MineSoundController` | ClientOnly, 맵 | cue 재생과 쿨다운 | 게임 이벤트 판정 |
| `MineInventoryController` | ClientOnly, HUD | 광물·재화·수레·상태 표시 | 자원 변경 |

## 2. 동기화와 이벤트

### 2.1 일반 광맥 marker

| 이름 | 타입 | 작성자 | 의미 |
|---|---|---|---|
| `VeinId` | string | 맵 설정 | D6 논리 ID |
| `ReserveStage` | integer | 서버 | 0~3 현재 stage |
| `OreType` | string | 서버/설정 | `stone`/`iron`/`gold` |
| `VisualRevision` | integer | 서버 | stage 또는 oreType 변경마다 증가 |

`OreType × ReserveStage`로 승인된 RUID를 선택한다. RUID가 누락되면 마지막 유효 스프라이트를 유지하고 ID 포함 오류를 남긴다. 빈 RUID는 사용하지 않는다.

### 2.2 행동·중요 이벤트

일꾼은 `VisualEventSequence`, `VisualEventKind`, `VisualEventCellX/Y`를 제공한다. 종류는 `move`, `mine_success`, `mine_fail`, `load_success`, `unload_success`다. 클라이언트는 아직 처리하지 않은 sequence만 한 번 처리한다.

희귀 입고와 특별 광맥 출현은 일반 행동 scalar와 분리한 **중요 이벤트 채널**을 쓴다. 이벤트에는 단조 증가 ID, `kind`, `mineId`, 위치, 광물/보상 요약을 포함한다. 재접속/지연 때 중복 재생하지 않되, UI가 놓치면 HUD 현재 상태로 복구 가능해야 한다.

| 중요 kind | 필수 반응 |
|---|---|
| `special_vein_spawn` | 월드 전용 marker, 토스트, 지도 위치, HUD 아이콘, cue 1회 |
| `rare_ore_unload` | Depot 강조, 희귀 광물·패시브 HUD 갱신, cue 1회 |
| `sale_completed` | 골드/크리스탈 변화 강조. 자동화는 계속 진행 |
| `appearance_obtained` | 피스·희귀도·도감 변화 표시 |

## 3. 렌더링 규칙

- stage 0은 고갈 형태, 1~3은 증가하는 광석 크기·광택으로 표현한다. 0→1/1→2/2→3은 0.25초 회복 효과 1회다.
- `mine_success`는 해당 일꾼 위치 파편과 `mine_hit`, `unload_success`는 Depot 강조와 HUD 수치 강조를 같은 sequence에서 각 1회 실행한다.
- 특별 광맥 marker는 활성 목록에서 제거되면 즉시 연출을 취소한다.
- 선택 링은 프로그램 편집기의 선택 WorkerIndex와 일치한다. HUD는 최대 5명 상태를 그리되, 상세 손/수레는 선택 일꾼을 우선 표시한다.
- 모든 임시 파티클·타이머·사운드 핸들은 map unload에서 정리한다.

## 4. 사운드 재생 규칙

| cue | 이벤트 | 쿨다운 |
|---|---|---|
| `mine_hit` | `mine_success` | 일꾼별 0.25초 |
| `mine_empty` | `mine_fail` | 선택 일꾼별 0.8초 |
| `cart_load` | `load_success` | 일꾼별 0.25초 |
| `depot_unload` | `unload_success` | 전역 1틱 1회 |
| `special_vein_spawn` | 중요 이벤트 | 스폰 묶음당 1회 |
| `rare_ore_unload` | 중요 이벤트 | 이벤트 ID당 1회 |

미승인 cue/RUID는 무음·무효과로 안전하게 건너뛰며 서버 시뮬레이션을 멈추지 않는다.

## 5. 수용 테스트

| # | 입력 | 기대 결과 |
|---|---|---|
| F5-1 | 세 oreType의 stage 0~3 반영 | 올바른 marker가 정확히 하나의 스프라이트를 표시 |
| F5-2 | 5명 동시 채굴·하역 | 원장은 각각 한 번만 반영되고 효과/사운드는 제한 내 재생 |
| F5-3 | 특별 광맥 1~2개 스폰 | 월드·토스트·지도·HUD가 같은 ID/위치를 표시 |
| F5-4 | 희귀 광물 Depot 입고 | 패시브 HUD·강조·cue가 1회, 자동화는 정지하지 않음 |
| F5-5 | 네트워크 지연/재접속 가정 | 중복 중요 연출 없이 HUD의 현재 상태로 복구 |
| F5-6 | map leave/Play 종료 | 남은 파티클·사운드 핸들러·클라이언트 오류 없음 |
