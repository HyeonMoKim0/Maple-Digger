# F5. 비주얼 · 사운드 기능 명세

> D5 구현 계약. 이 문서는 게임 디자인이 아니라 구현 책임, 상태 계약, 테스트 조건을 정의한다.

## 1. 책임 분리

| 모듈 | 실행 위치 | 책임 | 금지 |
|---|---|---|---|
| `VeinTickSimulator` | ServerOnly, 맵 | 광맥 stage·회복·채굴 결과의 권위 있는 계산 | RUID 선택, 효과음 재생 |
| `WorkerController` | ServerOnly, 일꾼 | 이동·채굴·싣기·하역 결과와 시각 이벤트 발행 | 클라이언트 파티클 직접 생성 |
| `VeinMarkerController` | ClientOnly, 광맥 마커 | 동기화된 stage를 0~3 스프라이트로 변환 | stage를 쓰거나 회복 계산 |
| `WorkerVisualController` | ClientOnly, 일꾼 또는 표시 자식 | 선택 링, 행동 반응, 파편 효과 | 프로그램·수레·창고 변경 |
| `MineSoundController` | ClientOnly, 맵 | 확정 이벤트의 효과음 재생·쿨다운 | 게임 이벤트 판정 |
| `MineInventoryController` | ClientOnly, HUD | 창고·손·수레 값 및 하역 강조 표시 | 자원 변경 |

## 2. 동기화 계약

### 2.1 광맥 마커

각 `VeinMarker`에는 다음 읽기 전용 동기화 값을 둔다.

| 이름 | 타입 | 작성자 | 의미 |
|---|---|---|---|
| `VeinId` | string | 맵 설정 | D6 광맥 ID |
| `ReserveStage` | integer | 서버 | 0~3 현재 매장량 |
| `OreType` | string | 맵 설정/서버 | `stone`, 이후 확장 가능 |
| `VisualRevision` | integer | 서버 | stage 또는 광물 종류가 바뀔 때 1 증가 |

`VeinMarkerController`는 `VisualRevision` 또는 `ReserveStage` 변경 시에만 렌더러를 갱신한다. 프레임마다 원장을 조회하지 않는다.

### 2.2 일꾼 시각 이벤트

각 Worker는 게임 결과가 확정된 뒤 다음 값을 갱신한다.

| 이름 | 타입 | 값 |
|---|---|---|
| `VisualEventSequence` | integer | 새 이벤트마다 1 증가 |
| `VisualEventKind` | string | `move`, `mine_success`, `mine_fail`, `load_success`, `load_fail`, `unload_success`, `unload_fail` |
| `VisualEventCellX/Y` | integer | 이벤트가 일어난 셀 |

- 클라이언트는 마지막 처리한 sequence보다 큰 이벤트만 한 번 처리한다.
- 이벤트는 게임 원장의 결과를 복제할 뿐이다. 네트워크 지연으로 효과가 늦어도 원장이나 UI 수치를 되돌리지 않는다.
- `VisualEventKind`는 실패 이유의 전문 로그를 대체하지 않는다. 로그는 기존 서버 로그를 유지한다.

## 3. 렌더링 규칙

### 3.1 광맥

| 조건 | 결과 |
|---|---|
| stage 0 | `StoneVeinEmptyRUID`를 표시하고 반짝임을 제거 |
| stage 1 | `StoneVeinStage1RUID` 표시 |
| stage 2 | `StoneVeinStage2RUID` 표시 |
| stage 3 | `StoneVeinStage3RUID` 표시, 약한 idle 반짝임 허용 |
| 0→1/1→2/2→3 | 새 RUID 적용 후 0.25초 회복 효과 1회 |
| 다른 값 또는 RUID 누락 | 빈 RUID를 쓰지 않는다. 마지막 유효 스프라이트를 유지하고 오류 로그를 남김 |

RUID는 마커 모델 또는 전용 리소스 설정에만 둔다. 스크립트 문자열 리터럴로 중복하지 않는다.

### 3.2 일꾼과 HUD

- 선택 링은 `_BlockProgramController:GetSelectedWorkerIndex()`와 같은 WorkerIndex에만 보인다.
- `mine_success`는 해당 Worker 위치의 파편 1회와 `mine_hit` cue를 발생한다.
- `unload_success`는 해당 DepotMarker 강조와 `MineInventoryController`의 창고 수치 강조를 같은 sequence에서 한 번만 실행한다.
- 모든 일시 효과는 0.3초 이내에 끝나며, 오브젝트가 map unload될 때 취소한다.

## 4. 사운드 재생 규칙

| cue | 이벤트 | 쿨다운 | 재생 위치 |
|---|---|:--:|---|
| `mine_hit` | `mine_success` | 일꾼별 0.25초 | 이벤트 셀 |
| `mine_empty` | `mine_fail` | 선택 일꾼별 0.8초 | 이벤트 셀 |
| `cart_load` | `load_success` | 일꾼별 0.25초 | 이벤트 셀 |
| `depot_unload` | `unload_success` | 전역 1틱당 1회 | 창고 셀 |
| `vein_recover` | marker stage 상승 | 마커별 1초 | 광맥 셀 |

모든 cue는 리소스 설정으로 RUID를 받아야 하며, 미승인/누락 cue는 무음으로 안전하게 건너뛴다.

## 5. 실패 처리와 로그

- 누락된 `VeinId`, 중복된 marker 연결, stage 범위 밖 값, RUID 누락은 `log_error`로 ID를 포함해 남긴다.
- 한 마커나 사운드 cue의 실패는 `VeinTickSimulator`와 `WorkerController`의 실행을 중단시키지 않는다.
- 클라이언트는 stage나 `VisualEventSequence`를 수정하지 않는다.

## 6. 수용 테스트

| # | 입력 | 기대 결과 |
|---|---|---|
| F5-1 | stage 0~3을 차례로 서버에서 반영 | 각 marker가 정확히 한 상태 스프라이트만 표시 |
| F5-2 | 채굴 성공 1회 | stage 감소, 파편·`mine_hit`가 1회, 원장은 한 번만 감소 |
| F5-3 | 고갈 광맥에서 반복 채굴 | 게임 로그는 유지되며 `mine_empty`는 쿨다운 이상으로 쌓이지 않음 |
| F5-4 | 두 일꾼이 같은 틱에 하역 | 창고 수량은 두 결과를 합산, 하역 cue는 해당 틱 1회 |
| F5-5 | 선택 일꾼 전환 | 선택 링과 HUD 대상이 같은 프레임에 바뀜 |
| F5-6 | map leave 또는 Play 종료 | 남은 파티클·사운드 핸들러가 없고 오류 로그 없음 |
