## 각 문서의 필수 수록 내용

### D0. 용어·테마 전환 명세 (가장 먼저, 반나절 분량)
모든 후속 문서와 코드 리스킨의 기준. **이 문서 없이는 기획서와 코드의 용어가 계속 어긋난다.**
- 농사→광산 개념 매핑표: 작물→광물, 심기→(광맥 노출/시추), 수확→채굴, 성장 stage→매장량 회복 단계, 드론→일꾼 캐릭터
- 코드 심볼 리네임 대상표: `FarmTickSimulator`→`VeinTickSimulator`, `DroneController`→`WorkerController`, `Farm/` 폴더명, 블록 라벨(H→M 등), 로그 프리픽스
- 확정 용어 사전(한글 표기 + 코드 영문 표기 병기) — 채팅 파서 키워드("캐", "실어")도 여기서 확정

### D1. 마스터 GDD (전체 조망, 2~3p)
- 핵심 루프 다이어그램: 블록 조립 → 일꾼 자동 실행 → 채굴/운반 → 자원 누적 → (방치) 광맥 재생 → 프로그램 개선
- 시스템 관계도: 5개 시스템(그리드 광산 / 틱 재생 / 자동화 엔진 / 블록 UI / 채팅 변환)의 데이터 흐름과 서버·클라 책임 분리(RPC 경계)
- 화면 목록: 메인 플레이 화면, 블록 조립 패널, HUD(자원), 인벤토리 창
- 마일스톤: 개발계획서 ③④⑤ 단계와 문서 D2~D5의 대응

### D2. 블록 명령 체계 명세서 (③단계 — 프로그래머 최우선 전달)
- **블록 카탈로그 전체표**: 이동(E/W/N/S), 채굴, 운반(싣기/내리기), **반복(횟수 지정)**, **조건(IF 광물 있음/없음, 수레 가득참)** — 각 블록의 파라미터, UI 라벨, 채팅 키워드
- **실행 모델 정의**: 틱당 1액션 유지, 반복 블록의 처리 방식(조립 시 전개 vs 런타임 인터프리트 — 권장안 명시), 중첩 허용 깊이
- **안전 규칙**: 프로그램 최대 길이, 무한루프 방지(최대 실행 틱), 맵 경계 처리, 실행 중 재실행 시 동작
- **채팅 자연어 확장 규칙**: 반복 표현("3번 반복해", "~까지"), 조건 표현("광물이 있으면 캐") 토큰 매핑표 — 기존 `ParseChatCommand` 규칙표의 확장판
- **채팅 입력 연결 방식**: 현재 미연결 상태이므로 입력 UI(텍스트 입력창) 요구사항 포함
- 수용 기준(acceptance criteria): "반복 3회 E이동 후 IF광물→채굴 프로그램이 로그로 검증됨" 같은 테스트 시나리오 목록

### D3. 자원·인벤토리 기획서 (④단계)
- 광물 종류 테이블(이름/희귀도/광맥 회복 속도/가치) — 밸런싱 수치 시트 포함(틱 주기, 회복 단계 수)
- 채굴→소지→운반→창고 저장 흐름과 소지 용량 규칙
- HUD·인벤토리 창 와이어프레임(텍스트 스케치)과 표시 항목
- 저장 정책: 세션 내 유지만 할지, DataStorage 영구 저장까지 갈지 명시

### D4. 일꾼 캐릭터 기획서 (⑤단계 전반)
- 랜덤 외형 생성 규칙(아바타 코스튬 슬롯 조합 풀), 일꾼 획득/추가 방식
- 다중 일꾼 운영: 캐릭터별 프로그램 배정 UX, 동시 실행 시 셀 충돌 규칙

### D5. 비주얼·사운드 폴리싱 가이드 (⑤단계 후반)
- 필요 리소스 목록: 광산 타일셋, 광물 스프라이트(단계별), 채굴 이펙트, 사운드(채굴/완료/버튼)
- 화면 연출: 채굴 히트 연출, 광맥 회복 시각화(스프라이트 단계 교체)

### D6. 광산 맵·콘텐츠 배치 기획서 (⑤b 선행)
- `farm01` 광맥·창고·일꾼 시작점의 ID/셀/광물/회복 주기를 맵 단일 기준으로 작성
- 스크립트에 하드코딩된 임시 좌표를 맵 설정으로 이전하고, 광맥/창고 marker 연결 규칙 확정
- 확장 광물 배치와 동선·타일 유효성 기준 정의

### F5/F6. 기능 명세
- D5/D6의 구현 책임, 동기화 데이터, 오류 처리, MapBuilder/Maker 검증 절차와 수용 테스트를 분리해 정의

## 진행 원칙
1. D0 → D1 → D2 순으로 작성하고, D2 완성 시점에 프로그래머 1차 전달(③단계 착수 가능).
2. D3부터는 D2 구현과 병행 작성한다. D5 구현 전에는 D6의 맵 데이터 단일 기준을 먼저 적용한다.
3. 문서 수정 시 이 로드맵의 표를 갱신하고, 확정 용어는 반드시 D0에 먼저 반영.
