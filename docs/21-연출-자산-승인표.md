### 1.3 광물 3종(돌·철·금) 구분 방법 — 결정 필요

위 두 자산은 **광물 종류 구분이 없다.** Q1-ⓐ를 문자 그대로 지키려면 `oreType × stage` **12개 서로 다른 스프라이트**가 필요한데, 그런 자산군은 검색으로 찾지 못했다.

| 방안 | 내용 | 평가 |
|---|---|---|
| A | `부유석` condition 4개를 stage로 쓰고, **광물 종류는 `SpriteRendererComponent.Color` 색조로 구분** | 자산 제작 0. 단 광물 종류가 **색으로만** 구분돼 D5 §8 **V1**("색 외의 형태로 구분")을 광물 축에서 어긴다 |
| B | `msw-painter`로 **12개를 직접 제작** | V1을 완전히 충족. 픽셀아트 12장 제작 비용 |
| **C ✅ 확정** | stage는 `부유석` condition, **광물 종류는 광맥 위에 작은 아이콘 뱃지**를 겹쳐 표시 | 자산 제작 0이면서 종류가 **형태로** 구분된다 |

**C로 확정 (2026-07-30, D8 C205).** D5 §3이 일반 광맥의 표현을 "돌/철/금의 형태·색·**작은 아이콘** + stage 0~3 크기·균열·광택 변화"로 규정하고 있어, 아이콘 뱃지는 기획 원문에 이미 들어 있는 방식이다. 승인된 아이콘(`docs/20` §0)을 그대로 재사용하므로 추가 검색도 필요 없다.

**구현 형태**

- 광맥 엔티티 = 부모(`SpriteRendererComponent` = `부유석` condition, stage에 따라 교체) + **자식 뱃지 엔티티**(`SpriteRendererComponent` = `docs/20` §0의 광물 아이콘).
- 뱃지는 광맥 스프라이트의 **좌상단 또는 상단 중앙**에 작게 얹는다. 크기는 원본 아이콘(28~32px)을 월드 단위로 환산해 약 0.3 unit 내외.
- 뱃지는 `oreType`으로만 결정되고 **stage에 따라 바뀌지 않는다.** stage 변화는 부모 스프라이트가 담당한다.
- 뱃지의 `SortingLayer`·`OrderInLayer`를 부모보다 **위**로 둔다. 같은 값이면 가려질 수 있다.
- 고갈(stage 0)에서도 뱃지는 유지한다 — "여기가 무슨 광맥이었는지"를 알아야 플레이어가 회복을 기다릴 수 있다.

## 4. 일꾼 (Q2 — 아바타 기반)

현재 일꾼은 **임시 몬스터 스프라이트**다. D5 §3은 "MSW 아바타 기반 실루엣"을 요구한다.

**방향**: `Worker` 모델을 `AvatarRendererComponent` + `CostumeManagerComponent` 기반으로 바꾸고, 광부 느낌의 기본 외형을 지정한다.

| 슬롯 | 검색 키워드 | 비고 |
|---|---|---|
| `cap` | "광부 헬멧", "안전모", "밀짚모자" | 광부 정체성을 가장 잘 전달 |
| `coat` / `longcoat` | "작업복", "멜빵바지" | |
| `weapon` | "곡괭이", "픽" | 채굴 도구. 손에 들면 역할이 즉시 읽힌다 |

**T-06(외형·도감·가챠)과 겹친다.** 이 티켓에서는 **기본 외형만** 지정하고, 피스 수집·장착 시스템은 T-06에 남긴다. 아바타 슬롯 매핑과 애니메이션 파이프라인은 `msw-avatar` 스킬 문서를 따른다.

> **미검색.** T-04 착수 시 `searchAvatarItems`로 위 3슬롯을 찾는다. 기본 아바타 RUID는 `getAvatarDefaults`로 얻는다.

|:-:|---|---|
